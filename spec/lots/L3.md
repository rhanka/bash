# Lot L3 — Full lexer and parser

Lot spec for the build lane (Room 2). Sources of authority: `spec/SPEC_EVOL_BASH_SANDBOX.md` ("EVOL":
decisions D1-D4, D6, D7, D14, D19-D21, D23; security invariants S3, S4, S10; Annexes A, B, D.2, D.7, E, F, G)
and `plan/PLAN_BASH_SANDBOX_V1.md` (lot L3, sections 4, 6 and 8). It builds on `spec/lots/L0.md` (gates G1-G8),
`spec/lots/L1a-1.md` and `spec/lots/L1a-2.md` (`kernel::mem` allocator, `Budget`, `KVec`, `KBox`, `KChunks`,
`reserve_scope`), `spec/lots/L1b.md` (WIT resources and driver loop), `spec/lots/L2.md` (`kernel::fiber`,

canonical-ABI binding), and `spec/lots/L10a.md` (parity recorder and replay runner). Where this document and
EVOL differ, stop and raise a spec issue.

- **Size.** 8 points, Strong. **Builder.** Sonnet 5.5; fallback Gemini 4 Argon. **Review.** Carbon, full
  review of every PR, dispatched on a green `make check`.
- **Branch.** `feat/l3-parser`, worktree `tmp/l3-parser`.
- **Outcome.** Replaces L2's subset `kernel::fiber::syntax` module with the complete bash lexer and parser
  across all 12 command kinds, all 12 redirection operators (including here-documents, here-strings, and
  `{varname}` descriptor variables), ANSI-C `$'...'` and `$"..."` quoting, multi-heredoc script normalization,
  full word/parameter/command/process/brace/tilde/glob ASTs, full arithmetic (`$(( ))`, `$[ ]`, `(( ))`,
  `for ((;;))`) and conditional (`[[ ]]`) ASTs, exact reference diagnostics and `line:col` positions, parser
  fuel and structural caps, explicit-stack VM execution for `If`, `For`, `While`, `Until`, `Subshell`, `Group`,
  `FunctionDef` (any compound body), `time [-p]`, fd-0 heredocs/herestrings, and deferred statement syntax
  errors, plus a deterministic seeded parser fuzz slice in `make check`.

## 1. Lane rules

1. No reference source and no reference package in the worktree. No network. The conductor (Room 1) writes the
   36 case files `test/cases/l3/*.case.json` from section 8, records `test/cases/l3/*.snap.json` against
   `just-bash@3.6.0`, and merges both to `main` before the worktree is created (PLAN section 6, steps 3-4). The
   builder never edits a committed case or snapshot and never runs or imports the reference engine; any needed
   new case is written by the builder and recorded by the oracle job (PLAN section 6, step 5).
2. Kernel: `no_std` on `wasm32-wasip2`, zero external crates in `Cargo.lock`, all heap allocations through
   `kernel::mem` against `&Budget`, `unsafe` only in `kernel/src/mem/` and `kernel/src/bindings/`. No recursive
   heap-owned AST drop chains (`Box`/`KBox` trees); every AST node table lives in flat `KVec` arenas so drop is
   bounded and `wasm32` stack usage stays flat (EVOL D4).
3. Host and tests: plain ES modules with JSDoc, Node built-ins only under `host/node/**`, `tools/**` and
   `test/**`, no Python and no Docker.
4. Never write to `/tmp`; scratch files go under the git-ignored `tmp/` of the worktree.
5. Commits through `make commit`, in English, without attribution trailers.

## 2. Scope

In scope:
- The two script-size gates of EVOL D1: pre-normalization `maxSourceBytes` check on UTF-8 byte length and
  UTF-16 code-unit count (exit `126`, `Status::LimitExceeded`, `limit_name: Some("maxSourceBytes")`), and
  post-normalization `1_000_000` UTF-16 code-unit parser gate (exit `2`, syntax error).
- Full `normalize` implementation (`rawScript: false` default), extending the built L2 algorithm in
  `kernel/src/fiber/syntax.rs` from one active heredoc to a FIFO queue: per-line stripping of all leading
  JS-whitespace on lines that start outside a quote and outside a heredoc body, multiline quote tracking with
  `\` escapes, `#` comment scanning without false quote toggles, verbatim heredoc bodies, and `rawScript: true`
  bypass (section 5.2).
- Full lexer (`kernel/src/fiber/syntax` lexer pass): operators, reserved-word classification by command/construct
  context, comments, `\` line continuations, `'...'`, `"..."`, `$'...'` ANSI-C quoting, `$"..."` locale
  double-quoting, `{varname}` fd-variable prefix before redirection operators, array subscript bracket balancing
  (`name[...]`), extglob group scanning (`@(...)`, `*(...)`, `+(...)`, `?(...)`, `<prefix>!(...)`), `${...}`
  balanced brace/quote scanning, `$(...)` command-substitution scanning (aware of quotes, `case ... in ... esac`
  patterns, nested `$((...))`/`((...))` shift operators, and inline heredoc bodies), `$((...))` vs `$( ( ... ) )`
  disambiguation, `((...))` vs `( ( ... ) )` disambiguation, `$[...]` legacy arithmetic scanning, `` `...` ``
  backtick scanning (outer vs double-quoted escape rules), `<(...)` / `>(...)` process-substitution scanning,
  and queued `<<` / `<<-` heredoc delimiter parsing plus body capture with `maxHeredocSize` enforcement.
- Full recursive-descent / explicit-budget parser producing a flat-arena AST for all 12 command kinds (`Simple`,
  `If`, `For`, `CStyleFor`, `While`, `Until`, `Case`, `Subshell`, `Group`, `FunctionDef`, `ArithmeticCommand`,
  `ConditionalCommand`), pipelines (`!`, `time`, `time -p`, `|`, `|&`), lists (`;`, `\n`, `&`, `&&`, `||`),
  deferred statement errors on stray `}` and `)`, all 12 redirection tokens, scalar/append/subscript/array
  assignments, all 15 `${...}` parameter expansion forms (plus parse-time vs expansion-time bad-substitution
  split), brace expansion (`{a,b}`, `{x..y[..step]}`), tilde expansion, glob/extglob word parts, full arithmetic
  expression AST (precedence, bases `2..=64`, array subscripts, dynamic bases, deferred syntax-error nodes),
  and full `[[ ... ]]` conditional AST (`||`, `&&`, `!`, `( ... )`, unary file/string operators, binary string/
  arith operators, `==`/`!=`/`=` pattern words including `!(...)`, and `=~` regex words).
- Cumulative parser budgets and work accounting: `Fiber::charge_work(1)` per lexed token and parse step
  (parse runs inside `Fiber::prepare` and is not fuel-sliced; exhaustion is `Fail::Work`, exit `126`),
  top-level `100_000`
  token cap, cumulative `100_000` token cap across nested sub-parsers, `200` nesting-depth cap across compound
  commands, sub-parsers, `[[ ( ... ) ]]`, and `$(( (...) ))`, `10_000` top-level statement-loop guard, and
  `1_000_000` cumulative parse-iteration cap.
- Resumable explicit-stack VM and word-expansion extensions required in L3 (`kernel/src/fiber/vm.rs`,
  `kernel/src/fiber/expand.rs`):
  - ANSI-C `$'...'` decoding into raw bytes / text in word expansion;
  - `If` / `elif` / `else` / `fi`, `For` (`for var [in words...]; do ...; done`, runtime identifier validation,
    default `"$@"` iteration when `in` is omitted, `maxLoopIterations` enforcement), `While` and `Until`
    (`maxLoopIterations` enforcement, condition `errexit`-suppression flag), `Subshell` `( ... )` (isolated
    variables, positional parameters, `cwd`, and shell functions), `Group` `{ ...; }`, `FunctionDef` with any
    compound command body, `time` / `time -p` pipeline timing summary on stderr, fd-0 input from `<<`, `<<-`,
    and `<<<` on simple and compound commands, deferred statement syntax errors on `}` and `)`, empty no-op
    `Simple` command execution (exit `0`), and `bash:cmd:*` coverage emission for every executed command kind.
- Parity suite `test/parity/l3.test.mjs`, limit and AST unit suites, and deterministic seeded parser fuzz slice
  (`test/l3-parser-fuzz.test.mjs` + native `cargo test` fuzz slice) running in `make check`.

Out of scope:
- Runtime evaluation of `${var:-...}` and the other 14 non-plain parameter operators, runtime execution of
  `$(...)` / `` `...` `` command substitution, `<(...)` / `>(...)` process substitution, `$((...))` / `$[...]` /
  `((...))` / `for ((;;))` arithmetic evaluation, `{a,b}` / `{1..5}` brace expansion, `~` tilde expansion, and
  pathname globbing (L4 — L3 parses all of them into their final AST nodes and validates their parse-time syntax
  errors).
- Runtime evaluation of `case` pattern matching and `[[ ... ]]` conditional expressions (L4/L5 consuming L8a's
  `kernel::glob` and `kernel::regex` — L3 parses `Case` and `ConditionalCommand` completely into AST).
- General file-descriptor table, output/file redirections (`>`, `>>`, `< file`, `2>&1`, `&>`, `<>`, `>|`,
  `{fd}>`), `set` / `shopt`, `errexit` / `nounset` / `pipefail`, `break` / `continue` / `return` / `exit`
  builtins, indexed and associative array storage, and namerefs (L5-L6).

## 4. Exact interfaces (`kernel::fiber::syntax`)

L3 replaces L2's flat `Term`/`Stage`/`Token` subset in `kernel/src/fiber/syntax.rs` (or `kernel/src/fiber/syntax/mod.rs`
with submodules) with an index-addressed arena AST backed entirely by `KVec<T>` in `&Budget`. Every node handle
is a `Copy` `u32` index or the built L2 `Span { start, end }` (`end` exclusive, count `end - start`) into a
typed `KVec` on `Ast` (or into `Ast::bytes`), so `Drop for Ast` frees flat vectors without recursion. The
module stays `pub(super)` inside `kernel::fiber`, exactly as built; `Program { source, ast }` in
`kernel/src/fiber.rs` keeps the normalized source alive next to the `Ast` for the whole exec.

Migration from the built L2 surfaces (all inside the allowed paths): `syntax::Word` (a `text`/`parts` span
pair) becomes `WordId`; `PartKind`/`Part` become `WordPart`; `Ast::word(index)` and the `tokens` table are
removed; `expand.rs` (`Expander`, `Scalar`, `Argument`, `Fields`) takes `WordId` and reads literal bytes from
`Ast::bytes` instead of source spans; `vm.rs` frames address `StmtId`/`CmdId` instead of `Term`/`Stage`
indexes. Limit values with no `I_*` constant in the read-only `kernel/src/limits.rs` (`maxLoopIterations`,
`maxHeredocSize`, `maxGlobOperations`) are read through `limits::index_of(name)` once per use site.

```rust
impl Ast {
    /// Lexes and parses a normalized (or raw) script into a flat-arena `Ast`.
    /// Extends the built L2 `Ast::parse(source, budget)`: `max_heredoc_size` is the resolved
    /// `maxHeredocSize` value and `work` charges one aggregate work unit per call (the caller in
    /// `Fiber::prepare` passes a closure over `Fiber::charge_work(1)`, mapping `Err` to `Error::Work`).
    /// `work` is called on every lexed token and parser step so pathological inputs honor `maxWorkUnits`.
    pub fn parse(
        source: &[u8],
        max_heredoc_size: u64,
        budget: &Budget,
        work: &mut dyn FnMut(u64) -> Result<(), ()>,
    ) -> Result<Self, Error>;
}
```

The builder may adjust internal field packing (for instance packing child `CondId` / `ArithId` pairs or adding
span tables for `Concat`) provided no AST drop recurses and every public behavior, limit, and AST invariant in
sections 5-9 holds.

## 5. Pre-execution, `normalizeScript`, and lexer specification

### 5.1 Two script-size checks and blank fast path (EVOL D1)

`Fiber::prepare` in the built `kernel/src/fiber.rs` already runs the steps below in this order; L3 keeps
that order and only extends steps 4 and 6. `stdin` size validation happens at fiber creation (`take_failure`
in `prepare`), unchanged from L2.

1. **Pre-normalization `maxSourceBytes` gate (exit `126`).** With `cap = shell.lim.vals[I_SOURCE_BYTES]` and
   `(units, bytes)` from the driver `script-overflow` report when present, else `(utf16_len(source),
   source.len())`: if `units > cap || bytes > cap`, finish early with exit `126`, `Status::LimitExceeded`,
   limit name `"maxSourceBytes"`, and stderr `bash: script input size limit exceeded (<cap> bytes)\n`.
2. **Pending creation failure.** `take_failure()` (stdin and input caps) ends the exec as in L2.
3. **Blank-script fast path (exit `0`).** If there is no overflow report and no invalid UTF-8 byte and every
   scalar is `syntax::space` (the JS `trim()` set `0x09..=0x0D`, `0x20`, `0xA0`, `0x1680`, `0x2000..=0x200A`,
   `0x2028`, `0x2029`, `0x202F`, `0x205F`, `0x3000`, `0xFEFF`), finish early with exit `0`,
   `Status::Completed`, empty output, and no `?` key added to `result.env`.
4. **Script normalization.** If there is no overflow report and `raw_script` is false, replace the source
   with `syntax::normalize(&source, &self.live)` (section 5.2); a memory error ends as `Fail::Mem`.
5. **Post-normalization `1_000_000` UTF-16 code-unit parser cap (exit `2`).** Count UTF-16 code units `U` of
   the (possibly normalized) script with `utf16_len` (`1` per BMP scalar, `2` per supplementary scalar, `1`
   per invalid byte). If an overflow report exists or `U > 1_000_000`, finish early with exit `2`,
   `Status::Completed`, and stderr
   `bash: syntax error: Parse error at 1:1: Input too large: <U> bytes exceeds limit of 1000000\n`.
6. **Parse.** Call the extended `Ast::parse` (section 4) with the resolved `maxHeredocSize`; map
   `Error::Memory` to `Fail::Mem`, `Error::Work` to `Fail::Work`, and every other error to an early finish
   with exit `2`, `Status::Completed`, and the error's `Display` line as stderr (the built mapping).

### 5.2 Full `normalize` behavior (multi-heredoc, quotes, comments)

This extends the built L2 `normalize` in `kernel/src/fiber/syntax.rs`, which already matches the reference
on single-heredoc scripts; L3 changes exactly one thing, the single `Option<(delimiter, strip_tabs)>`
becomes a FIFO queue `KVec<(Span, bool)>` (spans into the source line bytes) so several heredocs queued on
one line protect all of their bodies in order. There is no common-indent computation and no second pass.
Split the source on `\n` and process lines in order, carrying `quote: u8` (`0`, `b'\''`, or `b'"'`) and the
heredoc queue across lines, joining emitted lines with `\n`:

1. **Heredoc line.** If the queue is non-empty with front `(delim, strip_tabs)`: let `closing` be the line
   with leading `\t` bytes removed when `strip_tabs` is true, else the line unchanged. If `closing == delim`,
   pop the front and emit the line with all leading JS whitespace (`syntax::space` scalars) removed;
   otherwise emit the line verbatim. A space-indented closing line of a plain `<<EOF` therefore does not
   close the heredoc (it stays body text, and EOF ends the heredoc), and a space-indented closing line of a
   `<<-EOF` does not close it either.
2. **Other lines.** Let `outside` be `quote == 0` at line start. Emit the line with all leading JS
   whitespace removed when `outside`, else verbatim. Then scan the emitted line to update `quote` and queue
   heredocs:
   - a byte equal to the open quote closes it; inside `'...'` nothing else is special;
   - `\` outside `'...'` skips the next byte;
   - `'` or `"` while unquoted opens that quote;
   - `#` while unquoted, at byte `0` or directly after a JS-whitespace scalar, stops the scan (comment text
     such as `# don't` never toggles a quote and `<<` in a comment never queues a heredoc);
   - `<<` while unquoted and `outside`: consume an optional `-` (`strip_tabs`), skip `' '` and `'\t'`,
     consume an optional quote byte `q` in `['\'', '"']`, take the run of identifier bytes or `-`
     (`[A-Za-z0-9_-]`, a digit may lead); if the run is non-empty and `q`, when present, is matched by the
     same byte right after the run, push `(run, strip_tabs)` onto the back of the queue. `<<<` queues
     nothing (the run after `<<` starts at `<`, which is not an identifier byte).
   Every `<<` on the line is processed, so `cat <<A <<B` queues `A` then `B`, and both bodies stay verbatim
   (the command reads the last heredoc queued for its fd 0, section 7).

### 5.4 Disambiguation, quoting, and special lexical scanning rules

1. **Line continuations (`\\\n`).** Outside single quotes, `$'...'`, and quoted heredoc bodies, `\\\n` is
   removed completely before token boundaries are decided, advancing `line += 1` and resetting `col = 1`.
2. **Comments (`#`).** Outside quotes, expansions, and `((...))` arithmetic, `#` at the start of a token
   (start of input or after whitespace / operator / newline) consumes through the end of the line (not
   consuming `\n`). Inside `$(...)`, `#` at word start is a comment (so `$(echo hi # )` does not close on the
   commented `)`), whereas inside `$((...))` `#` is the base separator `16#ff`, never a comment.
3. **Reserved words and `{` / `}` / `!` / `[[`.**
   - Unquoted words `if`, `then`, `else`, `elif`, `fi`, `for`, `while`, `until`, `do`, `done`, `case`, `esac`,
     `function`, `time`, `{`, `}`, `!`, `[[` are recognized as their keyword token only in command-start position
     (start of script, after `\n`, `;`, `&`, `|`, `|&`, `&&`, `||`, `(`, `{`, `do`, `then`, `else`, `elif`, `!`,
     `time`, `;;`, `;&`, `;;&`), with `}` also recognized where a group can close, `]]` recognized inside
     `[[ ... ]]` (only when followed by whitespace, `;`, `&`, `|`, `)`, `<`, `>`, `\n`, or EOF), and `in` / `do`
     recognized after `for <word>` and `case <word>`. Notice `[[]]` (no space between `[[` and `]]`) is a single
     `WORD` (`bash: [[]]: command not found`, exit `127`), never `DBRACK_START`!
   - `{` is `LBRACE` only when followed by whitespace (`' '`, `'\t'`, `'\n'`) or EOF; `{echo` or `{a,b}` is a
     `WORD`.
4. **`((` vs `( (` and `$((` vs `$( (` disambiguation.**
   - When `((` appears in command position (not immediately after `for`, where `for ((` is always C-style `for`),
     scan forward tracking parenthesis depth (`depth = 2` after both `(`), single/double quotes, and `\` escapes:
     - If depth drops from `2` to `1` at a single `)` (not `))`) — e.g. `((echo a) && (echo b))` — or if the
       matching close at `depth == 0` is two separate `)` tokens separated by whitespace/newlines (`) )`), it is
       nested subshells: emit two separate `LPAREN` tokens (`(` `(`).
     - Otherwise if it closes with adjacent `))` (`depth` goes `2 -> 0` on `))`), emit `DPAREN_START`.
   - Likewise, inside word scanning at `$((`, if depth drops `2 -> 1` before `))` (for instance `$( (echo a) )`
     or multiline closing `) )`), treat it as command substitution `$(` starting with a subshell `(`, not
     arithmetic `$((...))`.
5. **`{varname}` file-descriptor variables.** When an unquoted word matches `^\{[A-Za-z_][A-Za-z0-9_]*\}$` and
   the character immediately following `}` (zero intervening whitespace) starts a redirection operator (`<`,
   `>`), emit `FD_VARIABLE` (value = `varname` without braces) followed by the redirection operator token. If
   whitespace follows `}`, it is a normal word/brace token.
6. **Numeric file descriptors.** An all-digit unquoted `NUMBER` token is treated as a redirection `fd` **only**
   when `token.end == next_token.start` (zero whitespace before `<` or `>`, e.g. `2>&1` has `fd = Some(2)`,
   whereas `echo 2 > file` passes `"2"` as an argument to `echo` and redirects fd 1!). Values exceeding `i32::MAX`
   are arguments, not fd prefixes.
7. **Extglob groups in words.** While reading an unquoted word segment, if `(` is encountered and the word buffer
   already ends with one of `@`, `*`, `+`, `?`, `!`, scan balanced parentheses `(...)` (respecting quotes and `\`
   escapes) into the same `WORD` token. Because standalone `!` at token start is dispatched as `BANG` before
   word scanning in `just-bash@3.6.0`, an unprefixed `!(a|b)` in argument or `case`-pattern position lexes as
   `BANG` followed by `LPAREN` (`syntax error near unexpected token \`('` / `Expected RPAREN, got LPAREN`),
   whereas `<prefix>!(a|b)` is a single `WORD`, and inside `[[ lhs == !(a|b) ]]` the conditional parser
   recombines `BANG` + `LPAREN ... RPAREN` into the pattern word when `RPAREN` is followed by `]]`, `&&`, or
   `||`. Preserve this exact tokenization so all error snapshots match.
8. **ANSI-C quoting `$'...'` and locale quoting `$"..."`.**
   - Outside single and double quotes, `$'` starts an ANSI-C quoted segment (inside `"..."`, `"$'a\nb'"` is not
     ANSI-C quoting: `$` and `'` remain literal inside double quotes, yielding `$'a\nb'`).
   - Scan until an unescaped `'`; if EOF is reached first, fail with `Error::Lexer` at the opening quote's
     line: `unexpected EOF while looking for matching \`''`.
   - Decode escapes inside `$'...'` in exact `just-bash@3.6.0` order:
     - `\a` -> `0x07`, `\b` -> `0x08`, `\e` and `\E` -> `0x1B`, `\f` -> `0x0C`, `\n` -> `0x0A`, `\r` -> `0x0D`,
       `\t` -> `0x09`, `\v` -> `0x0B`, `\\` -> `0x5C`, `\'` -> `0x27`, `\"` -> `0x22`.
     - `\xH` / `\xHH`: inspect the next `min(2, remaining_body_bytes)` bytes after `\x`. If that slice begins
       with at least one ASCII hex digit, parse its leading hex run (`1` or `2` digits) as a byte, append it
       to the current byte run (below), and advance past `\x` plus **both** inspected bytes even when the
       second is not a hex digit (`$'\x4G'` emits byte `0x04` and swallows `G`; `$'\x9\xz'` emits `0x09` then
       literal `xz`, because the second inspected byte is the next `\`). Otherwise emit literal `\x`
       (`0x5C 0x78`, so `$'\xz'` stays `\xz`) and advance by 2. Consecutive byte-run appends are decoded
       together as UTF-8 with per-byte Latin-1 recovery: valid UTF-8 sequences decode to their Unicode
       scalar value, while any ill-formed byte `b` (lone continuation, truncated lead, overlong, surrogate
       half, `> 0xF4`) becomes scalar `U+00XX` (`$'\xc3\xa9'` -> `é`, `$'\xff'` -> `ÿ`); the run ends at the
       first body byte or escape that is not a `\x` byte append.
     - `\uH`..`\uHHHH`: inspect the next `min(4, remaining_body_bytes)` bytes after `\u`. If that slice begins
       with at least one ASCII hex digit, parse its leading hex run as a 16-bit value, emit that UTF-16 code
       unit / scalar, and advance past `\u` plus `min(4, remaining_body_bytes)` bytes; otherwise emit literal
       `\u` and advance by 2. Note `\U` is not a recognized escape in `just-bash@3.6.0` (`$'\U0001f600'` emits
       literal `\U0001f600`), and `\0` / NUL bytes are preserved inside the resulting string (`x=$'a\0b'; echo ${#x}`
       prints `3`).
     - `\NNN` (1 to 3 octal digits `[0-7]` starting immediately after `\`): parse the 1..=3 octal digits in
       base 8, emit that code unit, and advance past `\` plus those 1..=3 digits (`\0101` consumes `\010` =
       `0x08` followed by literal `1`).
     - `\cX`: if a body character `X` follows `\c`, emit byte `(X as u8) & 0x1F` and advance by 3; if `\c` sits
       immediately before the closing `'` (`$'\c'`), emit `0x07` (`0x27 & 0x1F`, matching `just-bash@3.6.0`).
     - Any other `\X` (including `\?` and `\U`): preserve both `\` and `X` literally.
   - Outside quotes, `$"..."` drops the leading `$` and lexes identically to `"..."`.
9. **Here-documents (`<<`, `<<-`).**
   - After emitting `DLESS` (`<<`) or `DLESSDASH` (`<<-`), peek horizontally (skipping `' '` and `'\t'`) on the
     same line to pre-scan the delimiter before advancing past it (the parser still consumes the delimiter word
     token on that line). If the delimiter contains an unclosed `'` or `"`, fail with `Error::Lexer` at
     that line (`unexpected EOF while looking for matching \`<q>'`); if it contains an unclosed `$(`, fail with
     `Error::Lexer` (`unexpected EOF while looking for matching \`)'`).
   - Strip quotes (`'...'`, `"..."`, `$'...'` -> raw inner chars, `$"..."`, and `\c` -> `c`) to form the closing
     delimiter string `D`, setting `quoted = true` if any quote or backslash appeared in the raw delimiter token.
   - When `\n` is reached and one or more heredocs were queued on the line just ended, consume their bodies
     immediately in FIFO order and emit one `HEREDOC_CONTENT` token per heredoc right after `NEWLINE`:
     - Read lines until a line `raw_line` (without `\n`) satisfies
       `(if strip_tabs { trim_leading_tabs(raw_line) } else { raw_line }) == D`, or until EOF is reached (EOF
       terminates an unclosed heredoc cleanly with **no** error!).
     - For `<<-`, strip all leading `\t` bytes from every body line.
     - For unquoted heredocs (`quoted == false`), join lines ending in an odd number of trailing `\` bytes with
       the next line (`\\\n` line continuation inside body).
     - After each body line is appended, if `body.len() > max_heredoc_size`, fail immediately with
       `Error::Lexer` at the current line: `Heredoc size limit exceeded (<max_heredoc_size> bytes)`
       (exit `2`).

## 6. Grammar, parse budgets, and complete diagnostic specification

### 6.1 Parser caps and diagnostic envelopes

1. **Diagnostic formatting (exit `2` on all parse and lexer failures):**
   - `Error::Lexer { line, message }` -> stderr `bash: line <line>: <message>\n`, `exit_code = 2`.
   - `Error::Parser { line, col, message }` -> stderr
     `bash: syntax error: Parse error at <line>:<col>: <message>\n`, `exit_code = 2`.
   - Early syntax exit leaves `stdout` empty (`""`) and does **not** set `?` in `result.env`.
2. **Caps enforced during lexing and parsing:**
   - **Top-level token cap (`100_000`):** After lexing a script (including its final `EOF` token), if
     `tokens.len() > 100_000`, fail at `1:1` with
     `Too many tokens: <tokens.len()> exceeds limit of 100000`.
   - **Cumulative token cap (`100_000`):** Maintain a shared `cumulative_tokens: usize` across the root parser
     and every nested sub-parser (`$(...)`, `` `...` ``, `<(...)`, `>(...)`, `${...}` sub-parses). Adding each
     sub-parser's `tokens.len()`: if `cumulative_tokens > 100_000`, fail at `1:1` with
     `Too many tokens: cumulative count exceeds limit of 100000`.
   - **Nesting-depth cap (`200`):** Maintain a shared `depth: u32` incremented on entering every compound
     command (`if`, `for`, `while`, `until`, `case`, `( ... )`, `{ ... }`, `(( ... ))`, `[[ ... ]]`), every
     nested sub-parser, every parenthesized conditional `( ... )` inside `[[ ... ]]`, and every parenthesized
     arithmetic `(...)` inside `$((...))`/`((...))`. When `depth > 200`, fail at the offending token's
     `<line>:<col>` with `Maximum parser nesting depth exceeded (200)`.
   - **Iteration caps:** Top-level statement loop `> 10_000` statements fails at current token `<line>:<col>`
     with `Parser stuck: too many iterations (>10000)`. Shared `parse_iterations > 1_000_000` across all loops
     fails at current token `<line>:<col>` with `Maximum parse iterations exceeded (possible infinite loop)`
     (the built L2 `Error::Steps` text; no oracle case triggers this cap, so keep the L2 text verbatim).

### 6.2 Grammar rules and exact parse-error table

1. **Statements, lists, and deferred errors:**
   - At statement start (after skipping `NEWLINE` tokens):
     - `DO`, `DONE`, `THEN`, `ELSE`, `ELIF`, `FI`, `ESAC`, `DSEMI` (`;;`), `SEMI_AND` (`;&`), `SEMI_SEMI_AND`
       (`;;&`), `SEMICOLON` (`;`), `AMP` (`&`), `AND_AND` (`&&`), `OR_OR` (`||`), `PIPE` (`|`), `PIPE_AMP`
       (`|&`) -> immediate `Error::Parser` at token `<line>:<col>`:
       `syntax error near unexpected token \`<lexeme>'`.
     - `RBRACE` (`}`) or `RPAREN` (`)`) at **root-list** statement start -> **consume** the token and emit a
       `Stmt` with `deferred_error = Some("syntax error near unexpected token \`<lexeme>'")` and `line = 1`.
       Deferred errors exist only in the root statement list: inside `{ ... }` / `( ... )` the matching token
       closes the compound, and in any other nested list (`if`/`else` bodies, loop bodies, `case` items) a
       stray `}` or `)` is an ordinary parse error at its own position, never deferred (for example
       `if echo ok; then echo done; else\n)\nfi` fails at `2:1` on `fi`).
   - `Stmt := Pipeline ( ('&&' | '||') NEWLINE* Pipeline )* ('&')? (';' | NEWLINE | EOF)?`.
   - If `;;`, `;&`, or `;;&` appears after a statement outside `case`, fail at its `<line>:<col>` with
     `syntax error near unexpected token \`<lexeme>'`.
   - Trailing `&&`, `||`, `|`, or `|&` followed by `EOF` (or non-command-start) parses an empty no-op
     `SimpleCmd` as the RHS command/stage without syntax error (`echo a &&` -> `a\n`, exit `0`; `echo a |` ->
     `""`, exit `0`; `!` -> negated empty command -> exit `1`).
2. **Pipelines:**
   - Leading `!` tokens toggle `negated` (`count % 2 == 1`). If zero leading `!` tokens precede `TIME`, consume
     `TIME`, optional `-p` (`WORD`/`NAME` with value `"-p"`), and then any `!` tokens after `time [-p]`. (A
     leading `! time ...` makes `time` a simple command name, not a pipeline timer.)
   - Stages connect via `|` (`pipe_stderr = false`) or `|&` (`pipe_stderr = true`), skipping `NEWLINE` tokens
     after the pipe operator.
3. **Compound commands:**
   - **`if`:** `IF cond=compound_list THEN body=compound_list (ELIF cond=compound_list THEN body=compound_list)* (ELSE else_body=compound_list)? FI redirs*`.
     - Empty `cond` before `;` fails on `expect(THEN)` -> `Expected THEN, got SEMICOLON`.
     - Empty `then`, `elif`, or `else` body fails at the closing `fi`/`elif`/`else` with
       `syntax error near unexpected token \`<tok>'`.
   - **`for` (word list):** `FOR var=(NAME|WORD|NUMBER|IN|DO|DONE) ( [NEWLINE* IN words*] (';' | NEWLINE) | ';'? ) NEWLINE* DO body=compound_list DONE redirs*`.
     - Notice an invalid identifier like `123` (`NUMBER` or non-identifier `WORD`: `for 123 in a b; do ...; done`)
       is **accepted at parse time** if it is a word/number token, and rejected at **runtime** when `for`
       executes with exit `1` and stderr `bash: \`<var>': not a valid identifier\n`!
     - Empty `body` between `do` and `done` fails with `syntax error near unexpected token \`done'`.
   - **`for (( ... ))` (C-style):** `FOR DPAREN_START init? (';' cond? (';' update?)?)? DPAREN_END (';' | NEWLINE)* (DO body=compound_list DONE | LBRACE body=compound_list RBRACE) redirs*`.
     - Fewer than 2 semicolons inside `(( ... ))` leaves missing clauses `None`; more than 2 semicolons leaves
       unconsumed tokens before `))` and fails via `expect(DPAREN_END)` (`Expected DPAREN_END, got <TOK>`).
   - **`while` / `until`:** `(WHILE | UNTIL) cond=compound_list DO body=compound_list DONE redirs*`.
     - Empty `cond` before `;` -> `Expected DO, got SEMICOLON`; empty `body` -> `syntax error near unexpected token \`done'`.
   - **`case`:** `CASE word IN (NEWLINE)* ( '('? pattern ('|' pattern)* ')' compound_list? ( ';;' | ';&' | ';;&' )? NEWLINE* )* ESAC redirs*`.
     - Missing `in` -> `Expected IN, got <TOK>`; missing `)` after pattern -> `Expected RPAREN, got <TOK>`;
       missing `esac` -> `Expected ESAC, got <TOK>`. Note `in` as pattern requires quoting or pattern context;
       `esac` without `(` ends the `case` unless preceded by `(` or `|`.
   - **Subshell `( ... )` and Group `{ ...; }`:**
     - `( compound_list? ) redirs*` and `{ compound_list? } redirs*` — note both `( )` and `{ }` (empty body)
       succeed with exit `0` in `just-bash@3.6.0`! Unclosed `(` fails with `Expected RPAREN, got EOF`; `{ echo a }`
       (where `}` is glued or missing `;`/`\n` so `}` is parsed as an argument word to `echo`) fails with
       `Expected RBRACE, got EOF`.
   - **Function definition:**
     - Form 1: `FUNCTION name '(' ')' NEWLINE* compound_cmd redirs*` or `FUNCTION name NEWLINE* compound_cmd redirs*`.
       If `name` is missing (`function { ... }`) or is a `NUMBER` (`function 123 { ... }`) or contains `=` /
       quotes, fail with `Expected function name`. Hyphenated/colon/dot names (`foo-bar`, `a:b`, `a.b`) are
       valid!
     - Form 2: `name '(' ')' NEWLINE* compound_cmd redirs*` where `name` is an unquoted non-`NUMBER` word not
       containing `=`. Note `123() { ... }` fails at `(` with `syntax error near unexpected token \`('`.
     - If the body is not one of the compound commands (`{ }`, `( )`, `if`, `for`, `while`, `until`, `case`,
       `[[ ]]`, `(( ))`), fail at the body token `<line>:<col>` with `Expected compound command for function body`.
   - **Arithmetic command `(( ... ))`:** Consumes tokens until `DPAREN_END`, reconstructs expression source
     preserving token spacing, parses via the arithmetic parser (syntax errors inside `(( ... ))` become
     `ArithExpr::SyntaxError`, reported at **runtime** with exit `1` and stderr
     `bash: arithmetic expression: syntax error: <msg> (error token is "<tok>")\n`, NOT exit `2` at parse time!),
     followed by trailing `redirs*`.
   - **Conditional command `[[ ... ]]`:**
     - Precedence: `||` (lowest) -> `&&` -> `!` -> `( expr )` -> unary (`-a`..`-z`, `-G`, `-L`, `-N`, `-O`, `-S`)
       / binary (`==`, `=`, `!=`, `=~`, `<`, `>`, `-eq`, `-ne`, `-lt`, `-le`, `-gt`, `-ge`, `-nt`, `-ot`, `-ef`)
       / single-word non-empty test, followed by `DBRACK_END` and trailing `redirs*`.
     - Exact parse errors inside `[[ ... ]]`:
       - Empty `[[ ]]` or missing RHS of `&&`/`||` -> `Expected conditional expression`.
       - Unary operator at `]]` (`[[ -f ]]`) -> `Expected operand after <op>`.
       - Extra word after unary or binary expression (`[[ -z a b ]]`, `[[ a =~ b c ]]`) ->
         `Expected DBRACK_END, got <TOK>`.
       - Missing RHS after `=~` (`[[ a =~ ]]`) -> `Expected regex pattern after =~`.
       - Missing RHS after any other binary operator (`[[ a == ]]`, `[[ a != ]]`, `[[ a < ]]`,
         `[[ a -eq ]]`): the `]]` token itself is consumed as the RHS word, so the failure is the following
         `expect(DBRACK_END)` at end of input -> `Expected DBRACK_END, got EOF` (position one column past
         the `]]`). There is no dedicated missing-operand message for these operators.
       - Unclosed `(` (`[[ ( a ]]`) -> `Expected RPAREN, got DBRACK_END`.
       - Inside `=~` RHS, collect adjacent tokens/parentheses (`(b|c)`) while tracking paren depth and spacing:
         if whitespace separates an unparenthesized extra word (`[[ a =~ b c ]]`), stop before `c` so `expect(DBRACK_END)`
         emits `Expected DBRACK_END, got NAME`.
4. **Simple commands, assignments, and redirections:**
   - Before the command word, accept any mix of `ASSIGNMENT_WORD` (`a=1`, `a+=1`, `a[i]=1`, `a=(1 2)`, `a+=(3)`)
     and redirections (`[NUMBER | FD_VARIABLE] redir_op target`).
   - After the command word is seen, redirections may appear anywhere among arguments and are extracted into
     `SimpleCmd::redirs`. An argument token of the form `name=(...)` / `name+=(...)` (an `ASSIGNMENT_WORD`
     whose `(` is glued to `=`/`+=`) is one word token for every command (`echo a=(1 2)` prints `a=(1 2)`);
     only the declaration builtins (`declare`, `typeset`, `local`, `export`, `readonly`) later interpret it
     as a compound array assignment. A standalone unquoted `(` among arguments (`echo (a)`) fails at
     `<line>:<col>` of `(` with `syntax error near unexpected token \`('`.
   - Missing redirection target (`echo >`, `echo > ;`, `cat <<\n`):
     - For `<<` / `<<-` followed by newline/EOF/operator -> `Expected here-document delimiter`.
     - For all other redirection operators -> `Expected redirection target`.
5. **Word, parameter, and arithmetic sub-parsers:**
   - **Unclosed substitutions at parse time (all exit `2`):**
     - Unclosed `${` (`echo ${x`) -> `Parse error at 0:0: unexpected EOF while looking for matching '}'`.
     - Unclosed `$(` or `<(` or `>(` -> `Parse error at <end_line>:<end_col>: unexpected EOF while looking for matching \`)'`.
     - Unclosed `` ` `` -> `Parse error at <end_line>:<end_col>: unexpected EOF while looking for matching \`\`'`.
   - **Parse-time vs deferred `${...}` errors:**
     - `${}` (empty) -> valid, expands to `""` (`ParamExpand { parameter: "", op: None }`).
     - `${#}`, `${#@}`, `${#*}` -> valid parameter-count forms.
     - `${#var-word}`, `${#var/a/b}`, `${#var#p}`, etc. (operator after `#var` other than `:` slice) ->
       **parse-time** `Error::Parser`: `${#<rest>}: bad substitution` (exit `2`).
     - `${var!ref}` (`!` after parameter name) -> **parse-time** `Error::Parser`: `${<inner>}: bad substitution`
       (exit `2`).
     - `${ x}` (whitespace), `${%}`, `${a[0][0]}` (multi-subscript), `${#x:1}` (length + slice), invalid
       `${var@Z}` transform -> **deferred** `ParamOp::BadSubstitution` / `LengthSliceError` (command fails at
       runtime with exit `1` and `bash: <text>: bad substitution\n`, script continues unless fatal).
   - **Arithmetic parser (`$((...))`, `$[...]`):**
     - Precedence from lowest to highest: `,` -> `= *= /= %= += -= <<= >>= &= ^= |=` (right-assoc) -> `? :`
       (right-assoc) -> `||` -> `&&` -> `|` -> `^` -> `&` -> `== !=` -> `< <= > >=` -> `<< >>` -> `+ -` ->
       `* / %` -> `**` (right-assoc; negative exponent produces runtime error in L4) -> unary `+ - ! ~ ++ --` ->
       postfix `++ --` and primary (`number`, `base#digits` for `2 <= base <= 64` with `a-z`=10..35, `A-Z`=36..61,
       `@`=62, `_`=63, `0x`/`0X` hex, `0` octal when all digits `0-7`, clamping literals exceeding `2^53 - 1` or
       `i64` per L4 spec, `(expr)`, `$var`/`var`, `arr[expr]`, `$((...))`, `$(...)`, `` `...` ``).
     - Syntax errors inside `$((...))` (`echo $(( 1 + ))`) record `ArithExpr::SyntaxError`, so parsing succeeds
       and execution of that command emits `bash: syntax error: <msg> (error token is "<tok>")\n` with exit `1`
       and **continues** to the next statement!

## 7. L3 VM execution extensions and coverage hits

`kernel/src/fiber/vm.rs` and `kernel/src/fiber/expand.rs` remain strictly explicit-stack (`KVec<Frame>`, zero
Rust call-stack recursion per shell nesting level) and execute the following L3 constructs:

1. **Coverage emission (`cmd::coverage_id`):** Emit `"bash:cmd:SimpleCommand"`, `"bash:cmd:If"`, `"bash:cmd:For"`,
   `"bash:cmd:While"`, `"bash:cmd:Until"`, `"bash:cmd:Subshell"`, `"bash:cmd:Group"`, `"bash:cmd:FunctionDef"`
   at the start of executing each corresponding `Command` node when coverage is enabled.
2. **Deferred statement syntax error:** At the start of executing a `Stmt`, if `stmt.deferred_error` is `Some(msg)`,
   abort script execution immediately with `exit_code = 2`, **discarding/clearing fiber `stdout`** so top-level
   `stdout` is `""` (matching top-level syntax-error reporting in `just-bash@3.6.0`), and formatting stderr
   `bash: syntax error: Parse error at 1:1: <msg>\n` (`?` unset in `result.env`). If an earlier statement already
   terminated execution (for example on a limit), the deferred error never fires.
3. **ANSI-C `$'...'` word expansion:** `WordPart::AnsiCQuoted(span)` appends its decoded bytes verbatim with
   `quoted = true` (no `IFS` splitting, no globbing).
4. **`If`:** Evaluate clause `cond` statement lists in order (with an `in_condition` flag on the frame stack for
   future `errexit` in L5). On the first clause whose `cond` finishes with `exit_code == 0`, execute its `body`
   and return its exit code; if none is `0`, execute `else_body` if present, else return `0`.
5. **`For`:** Validate `var` matches `^[A-Za-z_][A-Za-z0-9_]*$`; if not, write
   `bash: \`<var>': not a valid identifier\n` to stderr and complete the command with `exit_code = 1` (script
   continues). Expand `words` (`None` -> current positional parameters `$1..$n`; `Some(empty)` -> 0 items;
   `Some(list)` -> word-expanded items capped by `maxArrayElements`). Before each iteration `iter = 1, 2, ...`,
   if `iter > maxLoopIterations`, fail with `exit_code = 126`, `Status::LimitExceeded`,
   `limit_name = Some("maxLoopIterations")`, preserving all stdout/stderr already emitted by earlier iterations,
   and appending `bash: for loop: too many iterations (<max>), increase executionLimits.maxLoopIterations\n` to
   stderr. Assign `var = item` in shell variables (persisting after loop completion) and run `body`. Exit code of
   a zero-iteration loop is `0`.
6. **`While` and `Until`:** Before each iteration `iter = 1, 2, ...` (checked **before** evaluating `cond`,
   matching `just-bash@3.6.0`!), if `iter > maxLoopIterations`, fail with `exit_code = 126`,
   `Status::LimitExceeded`, `limit_name = Some("maxLoopIterations")`, preserving prior stdout/stderr and
   appending `bash: <while|until> loop: too many iterations (<max>), increase executionLimits.maxLoopIterations\n`.
   Evaluate `cond`: `While` breaks if `cond_exit != 0`; `Until` breaks if `cond_exit == 0`. Otherwise execute
   `body` and update loop `exit_code = body_exit` (initial `exit_code = 0` if 0 body runs).
7. **`Subshell` `( ... )`:** Save a snapshot of variables, positional parameters, `cwd`, and `functions` on the
   explicit VM frame stack (unlike pipeline stages in L2, which keep function definitions in `just-bash@3.6.0`,
   an explicit `( ... )` subshell restores `functions` too!). Execute `body`, then restore the saved state while
   preserving `last_exit` = subshell exit code.
8. **`Group` `{ ... }` and `FunctionDef`:** `{ ... }` executes `body` in the current environment (empty `{ }` or
   `( )` exits `0`). `FunctionDef` binds `name -> CmdId` for any compound `Command` body (`{ }`, `( )`, `if`,
   `for`, `while`, `until`, etc.).
9. **`time` / `time -p` pipeline prefix:** Execute the pipeline normally (an empty pipeline after `time`
   still prints the summary and exits `0`); before applying pipeline exit status, append the timing summary
   to stderr in exactly one of these shapes: `\nreal\t<M>m<S>.<mmm>s\nuser\t<M>m<S>.<mmm>s\nsys\t<M>m<S>.<mmm>s\n`
   when `!time_posix`, or `real <S>.<cc>\nuser <S>.<cc>\nsys <S>.<cc>\n` when `time_posix`. The reference
   prints measured wall-clock values there, so the numeric fields are nondeterministic and are excluded from
   byte parity (EVOL Annex E.6): no oracle case in section 8 executes a timed pipeline, and gate 3 in
   section 9 checks only the shape. The kernel has no clock import, so it prints zeros
   (`0m0.000s` / `0.00`) in the same shapes; record this as a `DIVERGENCES.md` candidate in `BRANCH.md`.
   A `time` word in a non-initial pipeline stage, or after a leading `!`, is an ordinary command name
   (section 6.2.2), never this prefix.
10. **FD-0 heredocs (`<<`, `<<-`) and herestrings (`<<<`):** When a command has a redirection with `fd` equal to
    `None` or `Some(0)` and `RedirTarget::HereDoc { content, strip_tabs, quoted }` or `RedirOp::HereStr`,
    materialize its input into the command's `stdin` `KChunks` (`quoted: true` -> literal bytes; `quoted: false`
    -> expand `$VAR` / `${VAR}` in `content`; `HereStr` -> expand target word and append `\n`).
11. **Empty `SimpleCmd` (`name: None`, `assigns` empty):** Exits `0` after processing any fd-0 heredoc.
