# Lot L10a — Parity harness

Lot spec for the build lane (Room 2). Sources of authority: `spec/SPEC_EVOL_BASH_SANDBOX.md` ("EVOL":
decisions D1, D14, D19, D23; Annexes D, E, I) and `plan/PLAN_BASH_SANDBOX_V1.md` (lot L10a, section 6).
It builds on lot L0 as specified in `spec/lots/L0.md` (`make check` runs `node --test test/`; no
dependency; node 22) and assumes nothing about L0's internals beyond that spec. Where this document and
EVOL differ, stop and raise a spec issue.

- **Size.** 3.5 points. **Builder.** Codex Sol 6.1 at medium effort; fallback Sonnet 5.5. **Review.**
  Carbon, full review of every PR, dispatched on a green `make check`.
- **Branch.** `feat/l10a-parity-harness`, worktree `tmp/l10a-parity-harness`.
- **Outcome.** Two engine-agnostic tools, a *recorder* and a *replay runner*, with the file formats they
  share, proven on a mock engine. Later, the oracle job records snapshots from the reference engine with
  the recorder, and every build lot replays them on `@sentropic/bash` with the runner.

## 1. Lane rules

1. No reference source and no reference package in the worktree. No network. The harness never imports
   an engine by name: engines are reached only through an adapter module passed by path.
2. Node built-ins only (`node:test`, `node:assert`, `node:fs`, `node:path`, `node:crypto`, `node:url`,
   `node:child_process`, `node:util`). No dependency, no TypeScript build; plain ES modules with JSDoc.
3. Never write to `/tmp`; scratch files go under the git-ignored `tmp/` of the worktree.
4. Commits through `make commit`, no attribution trailer. English.

## 2. Scope

In scope: case and snapshot formats; the engine-adapter interface; the recorder (library and command
line); the replay runner; the divergence and exclusion handling; the parity report; a mock adapter; a
committed sample of cases with their snapshots; the skeleton of the API tier tests.

Out of scope: the adapter for `@sentropic/bash` (lot L2); the adapter for the reference engine and the
recording of real snapshots (oracle job, Room 1); generated differential testing (lot L11a); the cases of
other lots.

## 4. Formats

All files are UTF-8 JSON written in **canonical form**: object keys sorted by code unit at every level,
two-space indentation, `\n` line ends, one trailing newline, strings escaped as `JSON.stringify` does.
Writing the same value twice yields identical bytes. Both tools read with `JSON.parse` and reject unknown
top-level keys.

**Text and bytes.** Script output is byte data that an engine returns as JavaScript strings under the
contract of EVOL Annex D.2 (valid UTF-8 decoded, other bytes kept one character per byte). Snapshots store
those strings as JSON strings, unchanged; JSON escapes carry any code unit, lone surrogates included.
Inputs that must be arbitrary bytes (stdin, file content) use the `bytes` form below.

A *content* value is either a string (text, encoded as UTF-8 when given to the engine) or
`{ "base64": "<standard base64>" }` (raw bytes).

### 4.1 Case file

`test/cases/<lot>/<name>.case.json`. `<name>` matches `[a-z0-9][a-z0-9-]*`.

| Key | Type | Default | Meaning |
|---|---|---|---|
| `id` | string | required | `<lot>/<name>`; must equal the file's location |
| `title` | string | required | One line |
| `tags` | string[] | `[]` | Free labels (grammar area, command name, ...) |
| `files` | object: path -> content or `{content, mode}` | `{}` | Initial files; `mode` is an integer |
| `env` | object: name -> string | absent | Initial environment; absent means the engine's default |
| `cwd` | string | absent | Initial working directory; absent means the engine's default |
| `profile` | string | `"normal"` | Limit profile for the instance (divergence V1: parity cases run under `normal` unless the case says otherwise) |
| `engine` | object | `{}` | Extra constructor options passed through to the adapter untouched (for example `commands`) |
| `capture` | `{trace, coverage, fs}` booleans | `false`, `false`, `true` | What is recorded besides results |
| `steps` | step[] (at least one) | required | Executions run in order on **one** engine instance |
| `divergence` | string or null | `null` | An id of EVOL Annex I (`"V2"`, ...) when the case exercises an intended difference |

A step: `{ "script": content, "stdin": content?, "stdinKind": "text"|"bytes"?, "env": object?,
"replaceEnv": boolean?, "cwd": string?, "args": string[]?, "rawScript": boolean? }`. Absent keys are not
passed to the engine.

### 4.2 Snapshot file

`test/snapshots/<lot>/<name>.snap.json`, one per case.

| Key | Meaning |
|---|---|
| `case` | The case id |
| `caseHash` | SHA-256 (hex) of the case file's canonical bytes; a snapshot whose hash differs from its case is stale |
| `engine` | `{ "name", "version" }` reported by the adapter that recorded it |
| `status` | `"recorded"` or `"engine-defect"` |
| `steps` | For `recorded`: one result per step, `{ "stdout", "stderr", "exitCode", "env", "stdoutKind"? }`; `env` is an object |
| `fs` | Present when captured: `{ "<path>": entry or null }` for every path whose entry differs between the state after construction and the state after the last step; `null` means removed |
| `trace` | Present when captured: events in order, each `{ "category", "name", "details" }` after the filtering of 5.4 |
| `coverage` | Present when captured: the feature identifiers in hit order |
| `defect` | For `engine-defect`: `{ "step": index, "message": string }` |

A filesystem entry: `{ "kind": "file", "mode", "content": {"base64": ...} }`,
`{ "kind": "directory", "mode" }` or `{ "kind": "symlink", "target" }`. Modification times are never
recorded. No timestamp, host name, path of the machine or duration appears anywhere in a snapshot.

### 4.3 Exclusion file

`test/parity/exclusions.json`: `{ "divergences": { "<V-id>": "<reason>" }, "cases": { "<case id>":
"<reason>" } }`. A case is *excluded* when its `divergence` id is listed or its id is listed. The file
committed by this lot lists no divergence and no case (the mock engine has none); later lots fill it. A
case whose snapshot status is `engine-defect` is excluded with the reason `upstream-defect`.

## 5. Interfaces

### 5.1 Engine adapter

An adapter is an ES module with a default export:

```js
/**
 * @typedef {string | {base64: string}} Content
 * @typedef {{script: Content, stdin?: Content, stdinKind?: 'text'|'bytes', env?: Record<string,string>,
 *            replaceEnv?: boolean, cwd?: string, args?: string[], rawScript?: boolean}} Step
 * @typedef {{stdout: string, stderr: string, exitCode: number, env: Record<string,string>,
 *            stdoutKind?: 'text'|'bytes'}} StepResult
 * @typedef {{kind: 'file', mode: number, content: Uint8Array}
 *          | {kind: 'directory', mode: number}
 *          | {kind: 'symlink', target: string}} FsEntry
 * @typedef {{category: string, name: string, durationMs: number, details?: Record<string, unknown>}} TraceEvent
 *
 * @typedef {object} EngineSession
 * @property {(step: Step) => Promise<StepResult>} exec
 * @property {() => Promise<Map<string, FsEntry>>} readFs   every path of the filesystem
 * @property {() => TraceEvent[]} takeTrace                 events since the last call, in order
 * @property {() => string[]} takeCoverage                  feature ids since the last call, in order
 * @property {() => Promise<void>} dispose
 *
 * @typedef {object} EngineAdapter
 * @property {string} name
 * @property {string} version
 * @property {(init: {files: Record<string, Content | {content: Content, mode?: number}>,
 *                    env?: Record<string,string>, cwd?: string, profile: string,
 *                    engine: Record<string, unknown>,
 *                    capture: {trace: boolean, coverage: boolean, fs: boolean}}) => Promise<EngineSession>} create
 */
```

Rules: `exec` resolves for every script outcome; if it rejects or throws, the harness treats it as an
engine defect (5.2). `takeTrace` and `takeCoverage` return empty arrays when capture is off. An adapter
may throw from `create` with an error whose `code` is `"UNSUPPORTED"`; the case is then reported as
*not covered* for that engine, not as a failure.

### 5.2 Recorder

Library: `harness/parity/record.mjs` exports
`recordCase(adapter, caseObject) -> Promise<{status, snapshot?}>` and
`recordAll({adapter, casesDir, snapshotsDir, check, filter}) -> Promise<{recorded, unchanged, changed,
unstable, defects, missing, stale, orphans, unsupported, invalid, lines, failed}>`.
`status` is `recorded`, `engine-defect` (both with `snapshot`), `unstable` or `unsupported`. Outcomes are
returned as a status rather than thrown, so the recorder reports every case before it fails (deviation
from the first draft of this section, which returned the snapshot alone). A case directory may hold lot
subdirectories: `<lot>/<name>.case.json` has its snapshot at `<lot>/<name>.snap.json`.

Behaviour of `recordCase`:
1. Create a session, read the filesystem if `capture.fs`, run the steps in order, draining trace and
   coverage after each step, read the filesystem again, dispose.
2. Do this **three times** on fresh sessions. If the three results are not identical after
   canonicalization, the case is *unstable*: no snapshot is written and the recorder fails.
3. If `exec` rejects, write a snapshot with `status: "engine-defect"`, the step index and the error
   message with any absolute path of the machine replaced by `<path>`.

Command line: `node tools/parity-record.mjs --adapter <module path> --cases <dir> --out <dir>
[--filter <substring>] [--check]`.
- Without `--check`: writes or rewrites snapshots; prints one line per case
  (`recorded|unchanged|changed|unstable|engine-defect <id>`); exit code 1 if any case is unstable or if a
  case file is invalid.
- With `--check`: writes nothing; exit code 1 if any snapshot would change, is missing, or is stale.
  This is the command the oracle job uses to prove that committed snapshots are reproducible.
- Snapshots without a case file are reported as `orphan` and make `--check` fail.
- A case the adapter does not support (`UNSUPPORTED`) is reported `not-covered` in both modes, never `missing`
  or `stale`; without `--check` any earlier snapshot of that case is removed.

### 5.3 Replay runner

Library: `harness/parity/replay.mjs` exports
`defineParityTests({adapter, casesDir, snapshotsDir, exclusions, reportPath})`, to be called from a
`node:test` file. It registers one test per case, named by the case id, and one final test that writes
the report.

Per case:
- excluded -> skipped, with the reason in the skip message;
- adapter `UNSUPPORTED` -> skipped as `not covered`;
- snapshot missing or stale -> **fails** (`missing snapshot` / `stale snapshot`);
- otherwise run the steps as the recorder does and compare with the snapshot. The first difference is
  reported as: the field path (`steps[1].stderr`, `fs["/a/b"].content`, `coverage[17]`), the index of the
  first differing code unit or byte, and a window of 40 units on each side, non-printable units shown as
  escapes. Differences in other fields are then listed by path only.

### 5.4 Comparison rules

- `stdout`, `stderr`: exact string equality. `exitCode`, `stdoutKind`: exact.
- `env`: same keys and values.
- `fs`: same set of changed paths, same entries; file content compared as bytes.
- `trace`: same sequence of (`category`, `name`); for each event the same `details` keys, and the same
  values for every key **except** those ending in `TimeMs`; `durationMs` is never compared. The recorder
  applies the same filter when writing: `durationMs` is not stored; every `*TimeMs` key is kept with the value
  `null`, and the adapter must supply a finite number for it (a missing key is a difference).
- `coverage`: same sequence of identifiers.
- Fields absent from the snapshot because capture was off are not compared.

### 5.5 Parity report

Written to `reportPath` (default `tmp/parity-report.json`, canonical JSON) and summarized on stdout:
totals `cases`, `passed`, `failed`, `excluded` (by reason), `notCovered`, and the same counts grouped by
lot (the first path segment of the id) and by tag. The report lists failed case ids. Invalid case files
count as failed cases, named by their `<lot>/<name>`. Each suite passes its own `reportPath` (L10a uses
`tmp/parity-report-l10a.json`) so suites do not overwrite each other. It contains no
timestamp.

## 6. Mock adapter

`harness/parity/mock-adapter.mjs`: a deterministic toy engine, only for testing the harness. Name
`mock`, version `1`. A script is a list of lines, each one command:

| Line | Effect |
|---|---|
| `echo <text>` | Appends text and a newline to stdout |
| `err <text>` | Appends text and a newline to stderr |
| `bytes <hex>` | Appends the bytes to stdout as one character per byte and sets `stdoutKind` to `bytes` |
| `stdin` | Appends the step's stdin to stdout |
| `args` | Appends the step's args, one per line |
| `write <path> <text>` | Creates or replaces a file (mode 0o644), creating parent directories |
| `rm <path>` | Removes a file |
| `ln <target> <path>` | Creates a symlink |
| `cat <path>` | Appends the file content to stdout; exit code 1 and a message on stderr if missing |
| `setenv <name> <value>` | Sets a variable that persists to the result's `env` |
| `exit <n>` | Stops the step with that exit code |
| `cover <id>` | Records a coverage hit |
| `trace <category> <name> <key>=<number> ...` | Records a trace event; `durationMs` and any key ending in `TimeMs` are filled from the clock |
| `random` | Appends a random number to stdout (for the instability test) |
| `crash` | Makes `exec` reject with an error naming an absolute path |

The filesystem persists across the steps of a session; a fresh session starts from the case's `files`.
`engine.unsupported: true` in the case makes `create` throw `UNSUPPORTED`.

## 7. Sample and skeleton

- `test/cases/l10a/`: at least 12 cases for the mock engine, covering: plain text; every byte value 0-255
  on stdout; stdin as text and as bytes; args; non-zero exit; stderr; two steps sharing files; file
  created, modified, removed; symlink; env change; coverage; trace with time keys; `capture.fs` off; a
  case tagged with a divergence id. Their snapshots, recorded from the mock adapter, are committed under
  `test/snapshots/l10a/`.
- `test/parity/l10a.test.mjs` replays that sample through `defineParityTests` in `make check`.
- `test/api/tier-a.test.mjs` and `test/api/tier-b.test.mjs`: one `test.todo` per row of tiers A and B of
  EVOL Annex D.1 (six rows for A, three for B), each named after the row, to be filled by later lots.

## 8. Tests and exit gates

All in `test/parity/*.test.mjs`, run by `make check`.

1. **Canonical form.** Serializing an object with shuffled keys, nested three levels, yields identical
   bytes for 100 random permutations; the output ends with exactly one newline.
2. **Record then replay.** Recording the sample into a scratch directory under `tmp/` produces files
   byte-identical to the committed snapshots (0 differing byte); replaying them gives 0 failure.
   `parity-record --check` on the committed sample exits 0.
3. **Sensitivity.** For each of these mutations applied to a copy of one snapshot, replay fails, names
   the case and reports the right field path: one character changed in `stdout`; in `stderr`; `exitCode`
   changed; an `env` value changed; one byte changed in a file's content; a changed path added; a changed
   path removed; one coverage id changed; two coverage ids swapped; a trace `name` changed; a trace
   counter changed. Eleven mutations, eleven failures.
4. **Tolerance.** Changing a trace `durationMs` or a `*TimeMs` value in the mock's output does not fail
   replay, and those values are absent from the recorded snapshot.
5. **Stale and missing.** Editing a case without re-recording makes replay fail with `stale snapshot`
   and `--check` exit 1; deleting a snapshot gives `missing snapshot`; a snapshot without case gives
   `orphan` under `--check`.
6. **Instability.** Recording a case containing `random` exits 1, prints `unstable <id>` and writes no
   file.
7. **Engine defect.** Recording a case containing `crash` writes a snapshot with status `engine-defect`
   whose message contains `<path>` and no absolute path; replay skips the case with reason
   `upstream-defect`.
8. **Exclusions and coverage of engines.** A case whose divergence id is listed in a test exclusion file
   is skipped with that reason; an `UNSUPPORTED` case is counted as `notCovered`; neither counts as
   failed.
9. **Report.** For the sample plus the special cases above, the report's counts equal the expected
   numbers stated in the test, and two runs produce byte-identical report files.
10. **Bytes.** The 256-value case round-trips: every code unit 0-255 appears once, in order, in the
    replayed `stdout`, and the snapshot file is valid UTF-8.
11. **Validation.** A case file with an unknown key, a missing `steps`, an id that does not match its
    path, or an invalid name is rejected by both tools with a message naming the file and the key.
12. **Isolation.** A test scans `harness/parity/` and `tools/parity-record.mjs` and fails if any import
    specifier is not relative or `node:`, or is one of `node:http`, `node:https`, `node:net`, `node:dns`,
    `node:tls`, `node:dgram`, or if the text `fetch(` appears.
13. **Cost.** Replaying the committed sample takes less than 2 seconds on the build machine.
14. `make check` is green on a clean worktree, with the two API skeleton files reporting nine todo tests.

## 9. Conductor gate (outside this lot)

The oracle job writes an adapter for the reference engine against the interface of 5.1 and runs
`parity-record --check` on snapshots it recorded. Nothing in this lot depends on it. If the interface of
5.1 proves insufficient for that adapter, the change comes back as an amendment to this spec.
