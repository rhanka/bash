### 4.2 Allocator headroom, reserve scope, and `KChunks` migration

1. **Headroom configuration (`L1a-2` section 5.1).** Keep one kernel-wide value `largest_headroom: u64`,
   initially `0`. In `Shell::create` (and `exec_oneshot`), after the existing check
   `Resolved::byte_sum() > ceiling` has passed, set
   `largest_headroom = max(largest_headroom, lim.headroom())` and call `mem::set_headroom(largest_headroom)`
   (`lim.headroom()` is `64 MiB` for `normal`, `54 MiB` for `hardened`, `32 MiB` for `contain`, `8 MiB` for
   `micro`, EVOL Annex B). Do **not** take the current `mem::headroom().cap()` into the maximum: before the
   first explicit call it is the default one eighth of the ceiling (`232 MiB` under the `normal` ceiling),
   which would break `VFS + live + output + headroom = ceiling`. Several shells can share one instance, so
   the value only grows; a single `hardened` shell reserves its full `54 MiB` (`256 MiB` ceiling minus the
   `128 + 64 + 10 = 202 MiB` byte caps).
2. **Reserve-scope unwinding (`L1a-2` section 5.2).** When a fiber ends on `Fail::Mem(MemError::Limit(id))`,
   `Fail::Mem(MemError::Ceiling)`, `Fail::Output`, `Fail::Input`, or `cancel(...)` (L1b names in
   `kernel/src/fiber.rs`):
   - First drop transient execution state owned by the fiber (`script`, `stdin` unread chunks, VM frame stack,
     active pipeline stage buffers, `kept` call buffers) to return pages to the instance heap.
   - Run diagnostic message construction (`end_fail`, `finish_named`, `cancel_inner`) and `adapt.rs` result
     lowering inside `mem::reserve_scope(|| ...)` so formatting stderr and returning `ExecResult` cannot fail
     on `MemError::Ceiling`.
3. **Chunked byte storage (`L1a-2` section 5.3).** Replace contiguous `KBytes` with `KChunks` in:
   - `kernel/src/fs.rs`: regular-file content in `Node` (`read_file` materialises into `KBytes` only at the
     read boundary; `write_file` / `append` append chunks against `vfs.budget`, charging `maxFileSystemBytes`
     without `2x` reallocation spikes).
   - `kernel/src/fiber.rs`: `stdout`, `stderr`, `stdin`, custom-command `body`, and VM inter-stage pipe
     buffers (`take_stdout(max)` and `take_stderr(max)` call `KChunks::drain_front(max, sink)`, whose sink
     copies the drained slices into the returned buffer, so drained 64 KiB chunks are freed immediately
     rather than held until fiber drop). `host/core/driver.js` continues to
     decode drained `stdout` and `stderr` bytes via `decodeUtf8` (valid UTF-8 decoded, invalid byte sequences
     mapped one character per byte `U+0000..=U+00FF`, EVOL Annex D.2).

## 5. Default filesystem layout and initial shell state

### 5.1 Host-to-kernel initialization fixes (`host/core/facade.js`)

1. **Default layout (truthiness, not `undefined` checks).** `defaultLayout` is true exactly when
   `options.cwd` is falsy (absent or `""`) **and** `options.files` is falsy (absent). Any `files` object,
   even `{}`, disables it. The `fs` option plays no part: `new Bash({ fs })` with no `cwd` and no `files`
   also uses the default layout. Initial `cwd` is `options.cwd` when truthy, else `"/home/user"` with the
   default layout, else `"/"`. `HOME` is `"/home/user"` with the default layout, else `"/"`. Pass
   `shellConfig.defaultLayout` accordingly (L1b passed `false` and tested `!== undefined`; both change).
2. **`commands` filter.** When `Array.isArray(options.commands)` is passed to `new Bash(options)`, pass
   `commands: options.commands` in `shellConfig.commands` (`Some(list<string>)`); when omitted, pass
   `undefined` (`None`, meaning all registered standard kernel commands are enabled).
3. **Initial environment, in this insertion order:** `HOME`, `PATH` (`"/usr/bin:/bin"`), `IFS` (`" \t\n"`),
   `OSTYPE` (`"linux-gnu"`), `MACHTYPE` (`"x86_64-pc-linux-gnu"`), `HOSTTYPE` (`"x86_64"`), `HOSTNAME`
   (`"localhost"`, always), `PWD` (initial cwd), `OLDPWD` (initial cwd), `OPTIND` (`"1"`), then every entry of
   `options.env` in its own order (overriding an earlier value in place), then `SHELLOPTS` and `BASHOPTS`
   set last (so a caller value for them is replaced): `SHELLOPTS` = `"braceexpand:hashall:interactive-comments"`,
   `BASHOPTS` = `"globskipdots"`.
4. **`exported` flags** (sent per variable in `shell-config.env`; L1b sent `true` for all): `exported: true`
   for `HOME`, `PATH`, `PWD`, `OLDPWD` and for every key of `options.env` (no name check at construction);
   `false` for the others. At `exec` time, keys of the exec `env` option are marked exported only when the
   key is a valid shell identifier (an ASCII letter or `_`, then ASCII letters, digits or `_`), section 7.1.
5. **Readonly shell variables.** Mark `SHELLOPTS` and `BASHOPTS` as readonly in the shell's variable attributes
   table at `Shell::create`.
6. **Kernel `Config`.** Extend L1b's `shell::Config` (and its lowering in `adapt.rs`) with the
   `shell-config` fields L1b ignored: `default_layout`, `commands`, `process_info`, `coverage`.

### 5.2 Kernel VFS layout on `Shell::create` and `Shell::register`

When `Shell::create` runs against an in-memory `Vfs` (no host mount at `"/"`), initialize the filesystem
*after* any caller `options.files` have been staged into `root`, in this order. Directories are created
recursively with mode `0o755`; a directory that already exists is kept. If a path to create as a
directory is an existing regular file (for example `files: { "/dev": "x" }`), construction fails: the
kernel returns `invalid-config` and the facade constructor throws
`Error("EEXIST: file already exists, mkdir '<path>'")`. Files are written with mode `0o644`, replacing any
caller file of the same path. The facade detects this case synchronously, before staging, by checking
whether a normalized `files` key equals one of `/bin`, `/usr`, `/usr/bin`, `/dev`, `/dev/fd`, `/proc`,
`/proc/self`, `/proc/self/fd` (the first such directory in creation order is `<path>`); the kernel
refuses the same case with `invalid-config` as a backstop.

1. **System directories.** `/bin`, `/usr/bin`; then, only when `config.default_layout`, `/home/user` and
   `/tmp`.
2. **Devices.** Directory `/dev`, directory `/dev/fd`, then empty files `/dev/null`, `/dev/zero`,
   `/dev/stdin`, `/dev/stdout`, `/dev/stderr`.
3. **`/proc` synthetic files.** Directory `/proc/self/fd`, then the files below, using `process_info`
   defaults `pid = 1`, `ppid = 0`, `uid = 1000`, `gid = 1000` when `config.process_info` is `None`:
   - `/proc/version` -> `"Linux version 5.15.0-generic (just-bash) #1 SMP PREEMPT\n"`
   - `/proc/self/exe` -> `"/bin/bash"` (no trailing newline)
   - `/proc/self/cmdline` -> `"bash\0"` (`5` bytes: `62 61 73 68 00`)
   - `/proc/self/comm` -> `"bash\n"`
   - `/proc/self/status` ->
     `"Name:\tbash\nState:\tR (running)\nPid:\t<pid>\nPPid:\t<ppid>\nUid:\t<uid>\t<uid>\t<uid>\t<uid>\nGid:\t<gid>\t<gid>\t<gid>\t<gid>\n"`
   - `/proc/self/fd/0` -> `"/dev/stdin"`, `/proc/self/fd/1` -> `"/dev/stdout"`,
     `/proc/self/fd/2` -> `"/dev/stderr"` (no trailing newlines).
4. **Working directory.** When `config.cwd` is not `"/"`, create it recursively; here a failure is ignored.
5. **Command stubs (`0o644`).** For every active kernel command (every `Standard` command in the registry when
   `config.commands` is `None`, or those whose name is in `config.commands` when `Some`; plus `Network`
   commands only when `G_NETWORK` is granted and allowed by `config.commands`) and then for every name in
   `config.custom_commands`, write `/bin/<name>` and `/usr/bin/<name>` with exact bytes
   `"#!/bin/bash\n# Built-in command: <name>\n"`; a failed stub write is ignored. When
   `Shell::register(name)` is called later, write the same two stubs. Never create stubs for
   `test-commands` (`__*`).

## 6. Command trait, generated registry, coverage table, and `echo`

### 6.1 Command trait and `kernel/src/cmd/` contract

Create `kernel/src/cmd/mod.rs` with the zero-allocation-fast-path command contract:

```rust
#[derive(Clone, Copy, PartialEq, Eq)]
pub enum CommandKind {
    Standard, // listed in getCommandNames()
    Network,  // omitted from getCommandNames(); requires G_NETWORK grant
}

pub enum CmdPoll {
    Done(i32),
    Yield(KBox<dyn CmdFrame>),
    Host { frame: KBox<dyn CmdFrame>, req: HostReq },
}

pub trait CmdFrame {
    fn resume(&mut self, ctx: &mut CmdCtx<'_>, outcome: Option<Outcome<'_>>) -> Result<CmdPoll, Fail>;
}

pub struct CommandSpec {
    pub name: &'static str,
    pub kind: CommandKind,
    pub flags: &'static [&'static str],
    pub start: fn(&mut CmdCtx<'_>, &[KBytes]) -> Result<CmdPoll, Fail>,
}
```

`CmdCtx<'_>` exposes mutable borrows of the active stage's `stdin` (`&[u8]` or `KChunks` reader), `stdout` and
`stderr` writers (updating `output_used` against `maxOutputSize` and `live` against `maxLiveBytes`), `cwd`,
`env`, `vfs`, `limits`, `grants`, `fuel` charger (`charge_work(units)`), and `xpg_echo: bool` (`false` until
L6 adds `shopt`). Synchronous commands such as `echo` write directly to `ctx` and return `Ok(CmdPoll::Done(0))`
with **zero** `CmdFrame` heap allocations; multi-step or host-calling commands box their state via
`kbox_unsize!`.

Each command implementation file `kernel/src/cmd/<stem>.rs` exports:
```rust
pub const SPEC: &[super::CommandSpec] = &[ /* one or more CommandSpec entries */ ];
```
Parallel command lots in Waves W4+ add **only** `kernel/src/cmd/<stem>.rs`; no shared tracked Rust or JS file
lists individual command names.

### 6.2 Build-time generation (`kernel/build.rs` and `tools/build.mjs`)

1. **`kernel/build.rs` (Rust `std` only, zero crate dependencies).**
   - Emit `cargo:rerun-if-changed=src/cmd`.
   - List `src/cmd/*.rs`, skip `mod.rs`, sort `<stem>` lexicographically by ASCII byte order, and emit
     `$OUT_DIR/registry.rs` included by `kernel/src/cmd/mod.rs` via
     `include!(concat!(env!("OUT_DIR"), "/registry.rs"));`.
   - For each `<stem>.rs`, emit
     `pub mod cmd_<stem> { include!(concat!(env!("CARGO_MANIFEST_DIR"), "/src/cmd/<stem>.rs")); }`
     (a `#[path]` attribute cannot take `concat!`; `include!` can, and `super::` inside the file then names
     the `cmd` module). A command file therefore has no inner attribute or `//!` comment, and `mod.rs`
     declares no `mod <stem>;` of its own. Paths stay remapped by `--remap-path-prefix`, so gate G3 holds.
     Flatten every `cmd_<stem>::SPEC` into `pub static ALL_COMMANDS: &[&CommandSpec]`, sorted by
     `spec.name` (fail the build if two specs register the same `name` or if a `SPEC` is empty).
   - Also parse the static `name`, `kind`, and `flags` literals in each `src/cmd/<stem>.rs` to emit
     `pub static COVERAGE_FEATURES: &[&str]` and `pub fn coverage_id(feature: &str) -> Option<u16>` in
     `$OUT_DIR/registry.rs` (section 6.3).
2. **`tools/build.mjs` -> `dist/js/kernel/commands.js`.**
   - Scan `kernel/src/cmd/*.rs` (excluding `mod.rs`) with the exact same rule, collect all `CommandKind::Standard`
     command `name` literals sorted by UTF-16 code unit order, and write deterministic UTF-8
     `dist/js/kernel/commands.js`:
     ```js
     export const COMMAND_NAMES = Object.freeze(["echo"]);
     ```
   - `host/core/facade.js` imports `COMMAND_NAMES` from `../../dist/js/kernel/commands.js` and implements
     `bash.getCommandNames()` by returning the active standard command names for that `Bash` instance (filtered
     by `options.commands` when provided, excluding custom commands and `Network` commands, and working
     synchronously before any `exec` even in the browser entry).

   `substitute`, `print`, `printFirstLine`, `delete`, `deleteFirstLine`, `append`, `insert`, `change`, `hold`,
   `holdAppend`, `get`, `getAppend`, `exchange`, `next`, `nextAppend`, `quit`, `quitSilent`, `transliterate`,
   `lineNumber`, `branch`, `branchOnSubst`, `branchOnNoSubst`, `label`, `zap`, `group`, `list`,
   `printFilename`, `version`, `readFile`, `readFileLine`, `writeFile`, `writeFirstLine`, `execute`.
7. `jq:node:<Kind>` (`27` entries, exact order):
   `Identity`, `Field`, `Index`, `Slice`, `Iterate`, `Pipe`, `Comma`, `Literal`, `Array`, `Object`, `Paren`,
   `BinaryOp`, `UnaryOp`, `Cond`, `Try`, `Call`, `VarBind`, `VarRef`, `Recurse`, `Optional`, `StringInterp`,
   `UpdateOp`, `Reduce`, `Foreach`, `Label`, `Break`, `Def`.
8. `cmd:flag:<cmd>:<flag>`: for each registered `CommandSpec` (sorted by `spec.name`), for each `<flag>` in
   `spec.flags` in slice order (`cmd:flag:echo:-n`, `cmd:flag:echo:-e`, `cmd:flag:echo:-E` in L2).

When `shell.coverage` is `true`, emit coverage hits into `fiber.coverage_hits` (`KVec<u16>` drained by
`fiber.take_coverage()`):
- When a `SimpleCommand`, `Group`, or `FunctionDef` starts executing: emit `bash:cmd:<Kind>`.
- When a `SimpleCommand` whose bare command name is in the 59-entry `bash:builtin:*` set starts dispatch
  (**before** shell-function lookup, per EVOL Annex D.7): emit `bash:builtin:<name>`.
- `bash:expansion:word_glob`: once per argument word of a simple command, when its expansion starts (not
  for the command-name word, not for assignment values).
- `bash:expansion:word_split`: once per argument word that contains an unquoted parameter expansion while
  `IFS` is non-empty, whether or not a field boundary is found. A word made only of `$@` or `$*` takes a
  positional fast path with no `word_split` hit (EVOL Annex D.7 lets the snapshots fix such sites; no L2
  case captures coverage).
- **Generic flag-coverage hook:** immediately before calling `(spec.start)(ctx, args)` for a registered kernel
  command, iterate `arg` in `args` in order; for every `arg` whose bytes exactly equal a `<flag>` in
  `spec.flags`, emit `cmd:flag:<cmd>:<flag>`.

### 6.4 `echo` specification (`kernel/src/cmd/echo.rs`)

`SPEC`: `name: "echo"`, `kind: CommandKind::Standard`, `flags: &["-n", "-e", "-E"]`. Exit status is always 0.
`echo` charges no work unit (section 7.4).

1. **Options.** Leading arguments are options only when they equal one of five exact tokens; the first
   argument that is not one of them, and everything after it, is printed as text. Escape interpretation
   starts at `ctx.xpg_echo` (`false` in L2).

   | Token | Effect |
   |---|---|
   | `-n` | no trailing newline |
   | `-e` | escapes on |
   | `-E` | escapes off |
   | `-ne`, `-en` | no trailing newline and escapes on |

   Any other argument ends option parsing, including `--`, `-`, `-nE`, `-nn`, `-Ee`, `-z` (printed as text).
   A later token overrides an earlier one (`-e -E` leaves escapes off).
2. **Text.** The remaining arguments joined by one space (`0x20`), followed by `\n` unless `-n` was seen.
3. **Escapes (when on).** The text is read left to right; a backslash followed by one of the forms below is
   replaced by its output, and scanning resumes after the form. A backslash that is the last byte prints
   one backslash.

   | Form | Output |
   |---|---|
   | `\\` | `\` |
   | `\n` `\t` `\r` `\a` `\b` `\f` `\v` | `0x0a` `0x09` `0x0d` `0x07` `0x08` `0x0c` `0x0b` |
   | `\e`, `\E` | `0x1b` |
   | `\c` | nothing more: the rest of the text and the trailing newline are dropped (even without `-n`) |
   | `\0` then 0 to 3 octal digits | one **raw byte**: the octal value modulo 256 (`\0` alone is `0x00`) |
   | `\x` then 1 or 2 hex digits | one **raw byte** with that value |
   | `\x` with no hex digit | the two characters `\x` |
   | `\u` then 1 to 4 hex digits | that code point encoded as UTF-8 |
   | `\U` then 1 to 8 hex digits | that code point encoded as UTF-8; above `0x10FFFF`, the text `\U` and the digits as written |
   | `\u` or `\U` with no hex digit | the two characters `\u` or `\U` |
   | `\` then any other byte | the backslash and that byte, unchanged (`\q` stays `\q`) |

   Raw bytes for `\0` and `\x` matter: the reference treats such output as bytes, so `\0303\0251` and
   `\xc3\xa9` both print `é` once the driver decodes UTF-8 (EVOL Annex D.2), and `\0377` prints `ÿ`
   (`U+00FF`, invalid UTF-8 kept as one character per byte). Emitting the UTF-8 form of `U+00C3` instead
   would print `Ã©`. A `\u`/`\U` value in `0xD800..=0xDFFF` makes the reference return a lone UTF-16
   surrogate, which no byte sequence decodes to; L2 emits `EF BF BD` (`U+FFFD`) for it, and no case covers
   it (listed as an `upstream-defect` candidate in `GATE_L2.md`).

## 7. Shell language subset and resumable VM

### 7.1 Pre-execution checks, indentation normalization, and `result.env` semantics

These steps replace L1b's bootstrap pre-check (`Fiber::spawn`, then the first `Fiber::run`), in this order:

1. **Source size (EVOL D1).** Let `units`/`bytes` be the script's UTF-16 length and UTF-8 length: from
   `exec-opts.script-overflow` (`utf16-units`, `utf8-bytes`) when it is set, else computed from `script`
   (a scalar `<= U+FFFF` counts 1 unit, a larger one 2, an invalid UTF-8 byte 1). If
   `units > maxSourceBytes` or `bytes > maxSourceBytes`: status `limit-exceeded`, limit name
   `maxSourceBytes`, exit 126, stderr `bash: script input size limit exceeded (<maxSourceBytes> bytes)\n`.
   This corrects L1b, which treated every `script-overflow` as a limit result: `maxSourceBytes` is at least
   4 MiB in every profile, larger than the 3 MiB lowering cap of EVOL D6.4, so an overflowed script under
   the cap is a parser result. In that case go straight to step 5 with `units` (the kernel has no text to
   normalize or to test for blank content; a script over 3 MiB that is blank or whose indentation-stripped
   length is at most 1 000 000 units is a known D6.4 gap, not covered).
2. **Blank script.** If the script contains only white space as JavaScript `String.prototype.trim` defines
   it (tab, LF, VT, FF, CR, space, `U+00A0`, `U+1680`, `U+2000..=U+200A`, `U+2028`, `U+2029`, `U+202F`,
   `U+205F`, `U+3000`, `U+FEFF`), finish: status `completed`, exit 0, empty stdout and stderr, and
   `result.env` as in step 6 for an early end. No `?` is added.
3. **`stdin` size.** `cap = min(maxInputBytes, maxStringLength)`. When the initial `stdin` or the running
   total of `Fiber::write_stdin` exceeds `cap` bytes: status `limit-exceeded`, limit name `maxInputBytes`
   (`maxStringLength` when it is the smaller one), exit 126, stderr
   `bash: stdin size limit exceeded (<cap> bytes)\n`.
4. **Indentation normalization** (skipped when `raw-script` is true). The script is split on `\n`. A line
   that begins outside any quote loses its leading white space (the step 2 set); a line that begins inside
   a single- or double-quoted string continued from an earlier line is kept verbatim. Whether a line ends
   inside a quote is decided by reading it from its start state: outside quotes, `\` protects the next
   character, `'` and `"` open a quote, and `#` at the start of the line or after a white-space character
   starts a comment that ends the line's reading; inside `'...'` only `'` is special; inside `"..."`, `\`
   protects the next character and `"` closes. Heredoc bodies are kept verbatim: on a line that begins
   outside quotes, each `<<` or `<<-`, optional blanks, an optional `'` or `"`, a word of
   `[A-Za-z0-9_-]` and the same quote opens a pending delimiter; following lines are kept verbatim until a
   line equals the last pending delimiter (for `<<-`, after removing leading tabs), and that closing line
   loses its leading white space. Lines are joined again with `\n`. (L2 has no heredoc syntax, so a script
   that reaches the parser with `<<` is a syntax error; the line handling above still applies.)
5. **Parser length cap.** If the UTF-16 length of the normalized script exceeds 1 000 000: status
   `completed`, exit 2, stderr
   `bash: syntax error: Parse error at 1:1: Input too large: <units> bytes exceeds limit of 1000000\n`.
6. **Per-exec environment and `result.env`.**
   - `exec_env` starts as a copy of the shell variables, or empty when `replace-env` is true; then each
     exec `env` entry is set. Exported attributes start from the shell's, or empty with `replace-env`; each
     exec `env` key that is a valid identifier (section 5.1, item 4) becomes exported.
   - `cwd` and `PWD` when the exec `cwd` option is non-empty: if the exec `env` contains `PWD`, `PWD` takes
     that value and `cwd` is the option; else if an exec `env` was given, `cwd` and `PWD` both become the
     symlink-resolved form of the option when it exists in the VFS (the option as given otherwise); else
     `PWD` is the option as given. `PWD` becomes exported in all three cases.
   - `shell.env()` and `shell.cwd()` are never changed by an exec.
   - After each top-level statement, `?` is set to its exit status (not exported). A script that runs no
     statement (comment only) adds no `?`.
   - **Early end.** When the exec ends on a parse or lexer error (exit 2), on a bare assignment to a readonly
     variable (exit 1), on a limit (126), on abort or deadline (124), or at step 2, `result.env` is the
     **shell's** variables (as `shell.env()` returns them) with each exec `env` entry set on top: no `?`,
     no `PWD` change, and the shell's variables are kept even with `replace-env`. Stdout and stderr produced
     before the end are kept.

### 7.2 Lexer and parser subset (hard structural caps)

Parser caps (EVOL Annex B, fixed in every profile), each ending the exec with exit 2 before any statement
runs: more than 100 000 tokens (stderr
`bash: syntax error: Parse error at 1:1: Too many tokens: <n> exceeds limit of 100000\n`), nesting deeper
than 200 (message text `Maximum parser nesting depth exceeded (200)`), more than 1 000 000 parse steps
(message text `Maximum parse iterations exceeded (possible infinite loop)`). No L2 case covers the last two;
their `Parse error at <line>:<column>` position is settled by L3's snapshots.

1. **Operators and delimiters.** `&&`, `||`, `|&`, `|`, `;`, `\n`, `(`, `)`. Unquoted spaces and tabs separate
   tokens. `#` at the start of a token skips through the end of the line (before `\n`). Unsupported operators
   met in L2 (`&` background, `;;`, `<<`, `<`, `>`, etc.) return a deterministic syntax error (`exit_code = 2`,
   non-empty `stderr` prefixed with `bash:`).
2. **Word parts and quoting.** A word is an ordered list of parts (`Literal`, `SingleQuoted`, `DoubleQuoted`,
   `Escaped`, `ParamExpand`):
   - `'...'` (single quotes): every byte until the next `'` is literal; backslash has no special meaning.
     Unclosed `'` at EOF -> `exit_code = 2`, stderr
     `bash: line <start_line>: unexpected EOF while looking for matching \`''\n`.
   - `"..."` (double quotes, and `$"..."` locale quotes treated identically to `"..."`): parses literal text,
     `$VAR` / `${VAR}` / special `$?` `$$` `$!` `$#` `$@` `$*` `$0`..`$9` `$_` `$-`, and backslash escapes only
     when followed by `"`, `\`, `$`, `` ` ``, or `\n` (`\<newline>` is line continuation and removed; any other
     `\X` inside `"..."` keeps both `\` and `X`). Unclosed `"` at EOF -> `exit_code = 2`, stderr
     `bash: line <start_line>: unexpected EOF while looking for matching \`"'\n`.
   - Unquoted `\`: `\<newline>` is removed (line continuation, joining adjacent word parts if no whitespace
     intervenes); `\X` for any other byte `X` produces `Escaped(X)` (literal, immune to splitting/operators).
   - Parameter tokens outside single quotes:
     - `$` at EOF, or followed by whitespace, `"`, `'`, `;`, `|`, `&`, `(`, `)`, returns literal `"$"`.
     - `$` followed by one of `?`, `$`, `!`, `#`, `@`, `*`, `-`, `_`, or ASCII digit `0..=9` -> `ParamExpand` of
       that 1-char name.
     - `$` followed by an identifier (longest match) -> `ParamExpand(ident)`.
     - `${...}` -> scan to the matching `}`. With no matching `}` before the end of the script, the exec ends
       with exit 2 and stderr
       `bash: syntax error: Parse error at 0:0: unexpected EOF while looking for matching '}'\n` (a parser
       error with a fixed `0:0` position, unlike the quote errors above). Inner forms in L2: a name, a
       non-negative decimal number, or one special character `?` `$` `!` `#` `@` `*` `-` `_`; `${}`
       expands to the empty string. When the inner text starts with a character that cannot start any
       parameter (for example a space or `%`), the command that holds the word does not run: it fails with
       status 1 and stderr `bash: <inner>: bad substitution\n` (`<inner>` = the text between `${` and `}`,
       so `${ x}` prints `bash:  x: bad substitution`), and the script continues with the next command.
       Other inner forms (operators such as `${a-b}`, or `${1a}`) are L4 scope; L2 has no case for them and
       expands them to the empty string as a placeholder.
3. **Grammar (L2 subset).**
   - `script := linebreak (list linebreak)?`
   - `list := and_or ((';' | '\n') linebreak and_or)* (';' | '\n')?`
   - `and_or := pipeline (('&&' | '||') linebreak pipeline)*` (left-associative: `a && b || c` parses as
     `(a && b) || c`)
   - `pipeline := '!'* command (('|' | '|&') linebreak command)*` (`!` toggles logical negation per `!` count:
     odd count maps exit `0 -> 1` and non-zero `-> 0`; `|&` pipes both stdout and stderr of the left stage into
     stdin of the right stage; pipeline exit status before `!` is the rightmost stage's exit code)
   - `command := function_def | group | simple_command`
   - `function_def := NAME '(' ')' linebreak group | 'function' NAME ('(' ')')? linebreak group` (where `NAME`
     is an unquoted valid identifier not equal to a reserved word)
   - `group := '{' linebreak list '}'` (`'{'` is recognized in command position as a reserved word token, and
     `'}'` is recognized in command position following `;` or `\n`; missing separator before `}` or unclosed `{`
     is a syntax error with `exit_code = 2`)
   - `simple_command := ASSIGNMENT_WORD* WORD*` (at least one `ASSIGNMENT_WORD` or `WORD`). An `ASSIGNMENT_WORD`
     is recognized only before the first non-assignment `WORD`, where the unquoted prefix before `=` or `+=` is
     a valid identifier (section 5.1, item 4).

### 7.3 Word expansion, `IFS` splitting, assignments, and functions

1. **Variable lookup.**
   - `$?`: last pipeline exit code (`"0"` at script start).
   - `$#`: decimal count of active positional parameters (`0` at top level unless set; inside a function call
     `f a b`, `"2"`).
   - `$1`..`$9` and `${1}`..`${N}`: 1-based positional parameter (`""` when out of range); `${0}` / `$0` is
     `"bash"`.
   - `$*`: positional parameters joined by the first character of `IFS` (or `" "` when `IFS` is unset, or `""`
     when `IFS` is empty `""`).
   - `$@`: in double quotes `"$@"`, expands to zero words when `$# == 0` (if the word is solely `"$@"`; if
     adjacent text exists like `"x$@"`, `"x"` when `$# == 0` and `"x$1"`, `"$2"`, ... otherwise), and one
     separate unsplittable word per positional parameter when `$# > 0`; unquoted `$@` and `$*` expand each
     positional parameter and apply `IFS` word splitting to each.
   - `$$` and `$BASHPID`: decimal `pid` (`"1"` default). `$PPID`: decimal `ppid` (`"0"` default). `$UID` and
     `$EUID`: decimal `uid` (`"1000"` default). `$BASH_VERSION`: `"5.1.0(1)-release"`. `$-`: `"hBs"`. `$!`:
     `"0"`. `$_`: initially `""`; after each non-pipeline simple command, updated to the last expanded argument
     (or command name if zero arguments, or `""` on bare assignment); multi-stage pipelines preserve the outer
     `$_`.
   - Named variable `NAME`: look up active function local scopes inner-to-outer, then `exec_env`; unset yields
     `""`.
2. **String-length and element-count checks.**
   - The string check applies to every expansion done **without** field splitting: assignment values
     (bare and prefix), the command-name word, and argument words that contain no unquoted parameter
     expansion (or any argument word while `IFS` is empty). It compares the expanded value's UTF-16 length
     with `maxStringLength`; above it, the exec ends with status `limit-exceeded`, limit name
     `maxStringLength`, exit 126, stderr `bash: word expansion: string length limit exceeded (<maxStringLength> bytes)\n`.
     An argument word split on `IFS` is not checked here (`A=01234567; echo $A$A` passes a cap of 10, while
     `echo "$A$A"` and `B=$A$A` fail it).
   - Element caps, both with status `limit-exceeded`, limit name `maxArrayElements`, exit 126 (no `bytes`
     word in either message): one argument word whose splitting yields more than `maxArrayElements` fields
     gives stderr `bash: array element limit exceeded (<maxArrayElements>)\n`; otherwise a command whose
     argument list (the words after the command name) would exceed `maxArrayElements` entries gives
     `bash: expanded argument element limit exceeded (<maxArrayElements>)\n`. With a cap of 3:
     `A="a b c d e"; echo $A` gives the first, `A="a b"; echo $A $A` the second, `echo a b c` passes.
3. **`IFS` word splitting.**
   - Effective `ifs`: value of `IFS` in current env, or `" \t\n"` if `IFS` is unset. If `ifs == ""`, no word
     splitting occurs.
   - Classify characters of `ifs` into `ifs_ws` (`' '`, `'\t'`, `'\n'` present in `ifs`) and `ifs_non_ws` (all
     other characters in `ifs`).
   - Only bytes produced by unquoted `ParamExpand` are eligible for splitting; literal, escaped, single-quoted,
     and double-quoted bytes are sticky and never split.
   - Leading and trailing runs of `ifs_ws` on splittable segments are trimmed (unless glued to an adjacent
     quoted/literal part); each `ifs_non_ws` (with optional surrounding `ifs_ws`) delimits a field, and runs of
     `ifs_ws` delimit fields.
   - A word that has **no** quoted parts and expands to `""` is removed (elided); a word with any `SingleQuoted`
     or `DoubleQuoted` part that expands to `""` is kept as an empty-string argument `""`.
4. **`exec-opts.args` injection.** When `args` is non-empty, its elements are appended verbatim (no
   expansion, no `IFS` splitting) to the argument list of the first executed simple command **that has a
   command word**, after that command's own arguments, and are then consumed. A bare assignment does not
   consume them (case `l2/exec-isolation-and-options`: `MUT=leak` runs first and `echo` receives them).
5. **Simple command execution order (assignments, command word, readonly).**
   - **Bare assignments (`words.is_empty()`):** evaluate each `NAME=rhs` / `NAME+=rhs` left to right (expanding
     `rhs` as a single unsplit string; `+=` appends to existing value or assigns if unset). If `NAME` is
     readonly (`SHELLOPTS`, `BASHOPTS`), the whole exec ends at once with exit 1 and stderr
     `bash: <NAME>: readonly variable\n` appended to what was already produced (`result.env` per section
     7.1, item 6, early end). Otherwise the value is stored and the status is 0.
   - **Prefix assignments (`!words.is_empty()`):** each `NAME=rhs` / `NAME+=rhs` is evaluated left to right
     and stored in the shell's variables **before** the command and argument words are expanded, so the
     words see the new values: `X=1 Y=$X echo $X $Y` prints `1 1`, `A=hello echo "$A"` prints `hello`, and a
     prefix `IFS=:` splits that command's words. This is the reference behaviour (EVOL D1), not GNU bash's.
     Each assigned name is exported for that command only. A prefix assignment to a readonly variable stores
     nothing, writes `bash: <NAME>: readonly variable\n` to stderr ahead of the command's own output, and the
     command still runs (`SHELLOPTS=x missing` prints that line, then `bash: missing: command not found`).
     After the command, every prefix-assigned name gets its previous value back, or is unset if it had none.
   - **Command word.** The command-name word is expanded to **one** string, never split on `IFS`:
     `C='echo hi'; $C` fails with `bash: echo hi: command not found` (127). Inside that word `$@` and `"$@"`
     join the positional parameters with one space, and `$*` / `"$*"` join them with the first character
     of `IFS` (a space when `IFS` is unset, nothing when it is empty), so `f() { "$@"; }; f echo hi` fails
     with `bash: echo hi: command not found`.
   - **Empty command word.** When the command-name word expands to `""`: if every part of that word is an
     unquoted parameter expansion (`$E`, `${E}`), the first argument becomes the command name, or, with no
     argument, the command does nothing and returns 0; otherwise (any literal or quoted part, as in `"$E"`
     or `''`) the command fails with exit 127 and stderr `bash: : command not found\n`.
6. **Multi-stage pipelines.** A one-stage pipeline runs in the current shell. In a pipeline of two or more
   stages, the shell variables are saved before each stage and restored after it, so an assignment inside
   a stage never reaches the rest of the script (`P=changed | P=other` leaves `P` unchanged). Function
   definitions are not restored: `f() { echo in; } | echo z; f` prints `z` then `in`. `$_` keeps its value
   from before the pipeline.
7. **Command resolution order.**
   - **Name containing `/`:** resolve it against `cwd`. Missing: exit 127, stderr
     `bash: <name>: No such file or directory\n`. Directory: exit 126, stderr
     `bash: <name>: Permission denied\n`. Resolved path `/bin/<base>` or `/usr/bin/<base>` with `<base>` an
     active custom or kernel command: dispatch `<base>`. Otherwise, mode without any execute bit
     (`mode & 0o111 == 0`): exit 126, stderr `bash: <name>: Permission denied\n`. Otherwise the file is a
     user script, run by L5; in L2 it ends with exit 127 and stderr `bash: <name>: command not found\n` as a
     placeholder (no L2 case reaches it). A name with `/` is never recorded in the path table.
   - **Bare name**, in this order:
     1. Shell function: push a call frame on the explicit VM stack (`call_depth` + 1, checked against
        `maxCallDepth`), bind `$1..$n` to the arguments, run the body, pop the frame.
     2. Path table (item 8), when it holds the name.
     3. `PATH` search: `PATH` from the current variables, `"/usr/bin:/bin"` when unset. Split on `:`; skip
        empty entries; resolve a relative entry against `cwd`. For each entry, `<entry>/<name>` that exists
        and is not a directory: if it is `/bin/<name>` or `/usr/bin/<name>` and `<name>` is an active custom
        or kernel command, dispatch it (custom first, unless `bypass-custom` names it; else the kernel
        command from `ALL_COMMANDS`) and record `<name> -> <path>` in the path table; else if it has an
        execute bit it is a user script (placeholder above); else continue with the next entry. `PATH=''`
        therefore finds nothing.
     4. Fallback: when `/usr/bin` does not exist in the filesystem, an active custom or kernel command of
        that name is dispatched whatever `PATH` holds (this is how a host-backed `fs` without stubs runs
        commands, L7b).
     5. `#[cfg(feature = "test-commands")]`: a name starting with `__` dispatches `testcmd::run`.
     6. Otherwise: exit 127, stderr `bash: <name>: command not found\n`.
8. **Path table.** Each `Bash` instance (kernel `Shell`) keeps one table from command name to the path where
   a `PATH` search found it. It persists across `exec` calls of that instance (recorded oracle behaviour of
   `just-bash@3.6.0`; it is the one piece of shell state an exec leaves behind). Before a
   `PATH` search, a recorded path is re-checked: it must exist and not be a directory, and be either the
   stub of an active command (`/bin/<name>` or `/usr/bin/<name>`) or executable; on success it is used,
   otherwise the record is dropped and the search runs. Hence `echo a; PATH=''; echo b` prints both lines,
   and a later exec on the same instance with `PATH=''` still finds `echo`.

### 7.4 Explicit-stack resumable VM and limit messages

Represent execution as a heap-allocated `KVec<VmFrame>` (`StmtList`, `AndOr`, `Pipeline`, `SimpleCmd`,
`CmdActive`, `FuncCall`) on `Fiber`, charged to `fiber.live` (`maxLiveBytes`). **Never** recurse on the Rust/WASM
call stack when evaluating nested lists, groups, pipelines, or shell function calls.

| Limit name | Trigger | Exit | Exact `stderr` line (`\n`-terminated) |
|---|---|---|---|
| `maxCommandCount` | +1 before each pipeline stage runs, whatever its kind (simple command, assignment-only command, group, function definition), including stages inside groups and function bodies; ends when the count would exceed the cap (`A=1; B=2; C=3; D=4` fails on `D=4` with a cap of 3) | `126` | `bash: too many commands executed (><max>), increase executionLimits.maxCommandCount\n` |
| `maxCallDepth` | Incremented on shell function entry (`call_depth > max`) | `126` | `bash: <func>: maximum recursion depth (<max>) exceeded, increase executionLimits.maxCallDepth\n` |
| `maxWorkUnits` | Shared counter across the fiber and its `parent` chain. ## 9. Measurement protocol, budget table, `wasm-opt`, `slim` build, and Gate L2 go/no-go

Units in this section: `KB = 1 000 bytes`, `MB = 1 000 000 bytes`, `KiB`/`MiB` binary. `gzip` size means
`zlib.gzipSync(bytes, { level: 9 }).length` of one file. Every child process and every tool run by the
script gets `LC_ALL=C`, `TZ=UTC` and `TMPDIR=<worktree>/tmp/bench-l2/tmp` (nothing is written to `/tmp`).

### 9.1 Measurement script (`tools/measure-l2.mjs`, PLAN section 7, EVOL Annex H)

`node tools/measure-l2.mjs [--variant committed|minified|wasm-opt]` (default `committed`) measures one
variant and writes raw samples and summaries to `tmp/bench-l2/<variant>/results.json`. The `committed`
variant is the package tree as `make build` leaves it (`host/`, `dist/js/`). The two other variants are
built by the script into `tmp/bench-l2/<variant>/` as a copy of `host/` plus a `dist/js/` regenerated from
the same component, and are measured there; the committed `dist/` is never modified by a variant.

1. **Environment.** Record OS kernel, CPU model, Node version, rustc version, `wasm-tools` version,
   `binaryen` version, git commit and dirty flag. Before any sample, assert in a child that
   `await new Bash().exec("echo hi")` returns `{ exitCode: 0, stdout: "hi\n", stderr: "" }`; a failed
   assertion aborts the run with exit 1.
2. **Cold start `M1` and memory `M5`.** 30 rounds; each round spawns, in a random order fixed by a seeded
   generator (seed recorded), one fresh `node` child of each kind: `baseline` (an empty ES module),
   `cold-import` (`import("<tree>/host/index.js")` only), `cold-full` (import, `new Bash()`, first
   `await bash.exec("echo hi")`). A `cold-full` child reports `tImport`, `tNew`, `tExec` (each from
   `performance.now()` around its step), `tCold = tImport + tNew + tExec`, and `process.memoryUsage().rss`
   after the exec; a `baseline` child reports its `rss`.
   - `M1` = interpolated median of `tCold` over the 30 `cold-full` children; also report min, nearest-rank
     p95, and the medians of `tImport`, `tNew`, `tExec`, and of the `cold-import` total.
   - `M5` = median `rss` of `cold-full` minus median `rss` of `baseline`, in bytes.
3. **Warm metrics** in one child process: 20 discarded iterations, then N iterations with
   `N = max(1 000, the number reached when 2 000 ms have elapsed)`, each timed with `performance.now()`.
   - `M2`: `new Bash()` (no exec).
   - `M3a`: `await bash.exec("echo hi")` on one warm instance; also report `bash.execSync("echo hi")`.
   - `M_host` (report only, no target): `await bash.exec("noop")` with a registered custom command `noop`
     returning `{ stdout: "", stderr: "", exitCode: 0 }` (one `host-call`/`resume` crossing).
   Report interpolated median, nearest-rank p95 and min, in milliseconds.
4. **Sizes `M6`.** Raw and gzip bytes, per file and summed, for:
   - `M6-wasm`: `dist/js/kernel/kernel.core.wasm` (the core module the loaders compile); also report
     `dist/kernel.core.wasm` and `dist/kernel.component.wasm` for information.
   - `M6-js`: every `.js` file the tarball ships, taken from `npm pack --dry-run --json` (offline):
     `host/**/*.js` and `dist/js/**/*.js`. `M6-js raw` is the sum of their raw sizes; `M6-js gzip` is the
     sum of their per-file gzip sizes.
   - Groups of `M6-js` (each file in exactly one group): **glue** = `dist/js/kernel/kernel.js` and
     `dist/js/kernel/kernel.shims.js`; **registry** = `dist/js/kernel/commands.js`; **core entry** = the
     other files reached by static `import` from `host/browser.js` (transitively); **Node-only** = all
     remaining files (`host/index.js`, `host/node/**`). Annex H's provisional split reads: core entry
     (glue + registry + core entry group) `<= 45 KB` raw; Node-only `<= 40 KB` raw; whole set `<= 30 KB`
     gzip.
5. **Repetition.** The script runs steps 2 and 3 three times; the value reported for each timed or memory
   metric is the median of the three run values, and the three values are kept in `results.json`. Sizes are
   measured once (they are deterministic, gate G3).
